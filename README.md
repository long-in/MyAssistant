# MyAssistant

音声で対話できるデスクトップ AI エージェントです。

- 会話はナレッジ(Markdown)として蓄積され、次の会話で関連する内容が自動で想起されます。
- ナレッジの閲覧・作成、インターネット検索、コマンドによる作業も、声で依頼できます。

| 項目 | 内容 |
| --- | --- |
| フロントエンド | Next.js 16 (静的エクスポート) / React 19 / Tailwind CSS 4 / shadcn/ui |
| バックエンド | Tauri 2 (Rust) |
| 対応 OS | **macOS 専用(26.2 以上)** |

Windows / Linux は未対応です(コマンド実行が `/bin/sh` 前提、音声認識が Metal 前提のため)。

機能ごとの詳細設計は [docs/](docs/README.md) を参照してください。

## 機能

### 対話

- **LLM 対話** ([chat-flow.md](docs/chat-flow.md))
  - Anthropic(API キー)に対応し、チャットのモデルは左下のピッカーで切り替えます。Amazon Bedrock(Claude)は、コンテナ内の Claude Code 経由で使います。AI Link の「接続方式」で API か Bedrock のどちらか一方を選び(ワークは Bedrock 固定。登録済みのキー・AWS 設定は切り替えても消えません)、Bedrock のときは、すべての機能(チャット・校正・ナレッジの整理・スキルの選定・スキル名の英訳・宛先の提案)をコンテナ内の Claude Code で実行します。モデルは Claude Code の settings.json で決めます。端末内のモデルは、API 方式のときだけ使えます。
  - 端末内で動くローカル LLM(Qwen 2.5 7B)も選べます。キー不要・無料で、会話の内容は端末の外へ出ません。設定画面からダウンロードします(約4.7GB。[local-llm.md](docs/local-llm.md))。
  - 校正・ナレッジ整理・スキル選定のモデルと、LLM に渡すプロンプト(全文を編集でき、初期値へ戻せる)は、エージェントの設定の「AI Settings」にまとまっています。
  - 応答は読み上げ向けの短い話し言葉です。画面には Markdown(表・コード・Mermaid の図)で描画し、返答・コードブロックごとにコピーできます。
  - 読み上げ後は自動で音声入力が再開し、会話を続けられます。
- **会話の継続と切り替え** ([conversation-session.md](docs/conversation-session.md))
  - 切り替えを明示しない限り、会話は継続します(放置しても切り替わりません)。
  - 切り替わるのは、「新しい会話」ボタンを押したとき、または「話題を変えて」などの発話に「はい」と答えたときだけです。
  - アプリを再起動しても、前回の会話(直近のやり取りと実行ログ)から再開します。
  - 長くなった会話は自動で要約し、毎回送るトークンを抑えます。
- **パーソナルデータ(オプション)** ([user-profile.md](docs/user-profile.md))
  - 名前・呼ばれ方・年齢・居住地などを手動で登録すると、呼びかけや回答の調整に使います。
  - 会話からの自動抽出はしません。

### 音声

- **音声入力 (STT)** ([voice-input.md](docs/voice-input.md))
  - 次から選べます。
    - ローカルの Whisper(既定。初回にモデルをダウンロード)
    - Google Cloud Speech-to-Text
  - Whisper のモデルは `ggml-large-v3-turbo-q5_0.bin`(約574MB)または `ggml-small.bin`(約466MB)です。
  - Silero VAD で声のない入力を除き、無音への幻聴を防ぎます。
- **文字起こしの校正(オプション)**
  - エージェントの設定の「AI Settings」でモデルを選ぶと(エージェントごとに指定)、会話の文脈と訂正履歴から聞き間違いを直してから送信します。
  - 字幕から聞き取りを手で訂正すると、ナレッジに記録されて次の発話から反映されます。
- **音声出力 (TTS)** ([voice-output.md](docs/voice-output.md))
  - 次から選べます。
    - Google Cloud Text-to-Speech(日本語 / 英語を自動判別)
    - VOICEVOX CORE(端末内で合成。キー不要・無料。設定画面から約90MBを取得)
  - 字幕は読み上げの再生位置に合わせて表示されます。
  - キーが無ければ字幕だけで応答します。
- **常時音声待機(オプション)** ([wake-standby.md](docs/wake-standby.md))
  - 起動ワードを登録すると、対話画面を開いている間マイクを開いたままにします。
  - 起動ワードを含む発話があったときだけ依頼を受け付け、含まない発話は LLM へ送りません。

### ナレッジ

- **蓄積と整理** ([knowledge.md](docs/knowledge.md))
  - 会話は即座に「キャプチャ」として Markdown に残ります。
  - 未処理のログは、LLM が事実・決定・手順・学びなどの項目に分けて取り出し、同じ話題の既存ノートへ統合して「現在の内容」を書き直します(書き換える前の版は残り、ノートの「履歴」から戻せます)。
    - 会話での指摘・好みは記憶の候補、繰り返し使える手順はスキルの下書きとして提案し、承認したものだけ反映します。
    - 「棚卸し」で、似たノートの統合・長く更新されていないノートの見直しを提案します(AI は使いません)。
    - 実行タイミング: ナレッジ画面の「今すぐ整理」(手動のみ。自動では整理しません)
  - 保存先は設定で変更でき、Obsidian の vault としても開けます。
- **関連ノートの想起** ([knowledge-graph.md](docs/knowledge-graph.md))
  - ノートをタグ・リンク・同じ会話由来のつながりでグラフにします。
  - 発話に関連するノートを最大2ホップ辿り、要約をプロンプトへ渡します。
  - LLM やネットワークは使いません。

### 作業の依頼(Claude 選択時のみ)

- **ファイル操作** ([agent-file-tools.md](docs/agent-file-tools.md))
  - ナレッジの一覧・読み取り・検索・新規作成ができます。
  - 作成は承認制で、上書きはできません。
- **インターネット検索**
  - Anthropic のサーバーツールで、検索とページ取得を行います。
  - 検索ごとに追加料金がかかるため、設定でオフにでき、回数の上限も設定できます。
- **コマンド実行** ([agent-command-tasks.md](docs/agent-command-tasks.md) / [command-policy.md](docs/command-policy.md))
  - 「〜してください」という依頼に手順を提示し、音声で「はい」と承認すると実行します。
  - 制限:
    - `rm`・`sudo`・OS に影響するコマンドは常に拒否します。
    - 読み取り系以外のコマンドは、ナレッジのディレクトリ内でしか実行できません。
    - アプリのデータ(API キー・会話の記録・ほかのエージェントのデータ)の場所は、読み取りもできません。
    - 計画外・破壊的なコマンドと、許可リストへの追加は、画面のボタンでだけ承認できます(音声の「はい」では通りません)。
  - 許可・拒否・都度承認のコマンドは、設定画面の Command Policy で編集できます(実体はナレッジ内の `.my-assistant/command-policy.json`)。
  - コンテナ内の Claude Code(ワーク、Bedrock 方式)で拒否するコマンドは、Claude Code の settings.json の `permissions.deny` で決めます(雛形に `rm`・`sudo` などの初期値が入っています)。
- **サンドボックス** ([sandbox.md](docs/sandbox.md))
  - ワークのエージェントへの指示は、常に、エージェントごとの専用 Docker コンテナの中の Claude Code が受け持ちます(切り替えはありません)。パーソナルとリーダーは、AI Link の接続方式に Bedrock を選んだときだけコンテナで動きます。続きの指示は同じセッションで引き継ぎます。
  - コンテナから見えるのは、そのエージェントのナレッジ(`/knowledge`)だけで(ソースコードなどはナレッジ直下の担当フォルダ `/knowledge/data` に置く)、ほかのエージェントや `~/.aws` には届きません。
  - Claude Code の接続先は Amazon Bedrock(AWS の一時キー)です。モデルと許可するツールは、Claude Code の settings.json で決めます。パーソナル・リーダーは、AI Link の接続方式に Bedrock を選んだときだけコンテナで動きます(API 方式では、Anthropic・端末内のモデルを従来どおり使います)。
  - エージェントごとの環境変数(`sandbox.env`)と AWS の一時キーを、実行時にだけコンテナへ渡します。イメージは全エージェント共通で、Dockerfile は全体設定で編集します。エージェントごとに専用の Dockerfile を登録すると、そちらを優先します。
  - Docker が使えないときは、ホストでは実行せずエラーにします。

### スキル

- **決まった依頼への対応手順** ([skills.md](docs/skills.md))
  - 「朝の報告をして」のような依頼に使う手順を、スキルとして登録します(名前・説明・手順の本文)。スキルはエージェントごとに持ちます。
  - 保存先はナレッジの「Skills」フォルダで、Agent Skills 標準と同じ `Skills/<名前>/SKILL.md` の形式です。ナレッジ画面からも直接編集できます。
  - 発話のたびに軽量モデルが当てはまるスキルを最大3件選び、対話モデルが必要なときだけ手順の本文を読みます。全スキルを毎回送らないので、トークンを抑えられます(スキルがなければ何も呼びません)。
  - チャットの入力欄で「/」を打つとスキルの候補が開き、選ぶと選定を省いてその手順で進めます(コンテナ内の Claude Code で会話するエージェントを除く)。
  - スキル画面(左メニューの「Skills」)で、一覧・追加・編集・削除ができます。会話からも、「スキル」と言って作成・更新・削除を頼めます(更新と削除は承認制)。スキル画面の「エクスポート」「インポート」で、全スキルをJSONファイルへ書き出し・取り込みできます(同名があれば、取り込み前に上書きするか飛ばすかを選びます)。
  - 手順はあくまで指示文で、ファイル作成やコマンド実行には通常どおりの承認と制限が適用されます。

### ワークスペース

- **パーソナルとワーク** ([workspace.md](docs/workspace.md))
  - 従来の機能は「パーソナル」です。仕事用に「ワーク」を追加し、その中に最大30件の「ワーキングエージェント」を作れます。
  - 会話・ナレッジ・設定・API キーは、パーソナルとエージェント、エージェント同士で共有しません。
  - エージェントごとに名称とイメージカラー(30色から選択、重複不可)を付け、どのエージェントと話しているかを画面で見分けられます。
  - 左メニューで切り替えます。ほかのワークスペースの設定を写すこともできます(API キー・パーソナルデータは選んだときだけ)。
- **リーダー** ([workspace.md](docs/workspace.md))
  - ワークの機能を有効にすると作成される、エージェントのまとめ役です(最初はパーソナルだけで、全体設定の「Work」で説明を読んで承諾すると有効になります。エージェントを作る前に必要です)。各エージェントへ指示を配布し(宛先は自分で選択)、タスクの進捗(実行中・承認待ち・完了・失敗)を、リーダーのチャット画面の右に出る台帳で確認します。
  - ほかのエージェントと同じチャット(音声入力・読み上げ付き)で話せます。AI にできるのは、台帳の参照と配布の下書きまでで、配布は宛先を確かめた利用者が押したときだけです。会話はナレッジ整理の対象です。
  - エージェントの会話・ナレッジ・結果の本文は読みません。専用の API キー(他のワークスペースからコピー可)と、行動原理・役割を書くリーダープロンプトを持ちます。宛先の提案は、過去に配布した指示の履歴だけが根拠です。

### その他

- **メニューバー常駐:** ウィンドウを閉じてもメニューバーに残り、アイコンのクリックで再表示します。終了はメニューから行います([frontend.md](docs/frontend.md))。
- **バックアップ:** 設定(API キーを除く)を JSON でエクスポート・インポートできます([data-and-settings.md](docs/data-and-settings.md))。
- **プロキシ:** 外向きの通信(AI・音声・モデルの取得・AWS)を、プロキシ経由にできます。プロキシは全体設定で複数登録して既定を決め、エージェントごとに使うものを選べます([proxy.md](docs/proxy.md))。
- **デバッグモード(オプション):** API の通信と文字起こしをナレッジ配下に記録し、画面で確認できます([debug-log.md](docs/debug-log.md))。

### 対応モデル

| プロバイダー | 軽量 | 高性能 |
| --- | --- | --- |
| Anthropic | Claude Haiku 5.5 | Claude Sonnet 5.5 / Claude Opus 5.5 |
| Amazon Bedrock | (コンテナ内の Claude Code の settings.json で決める) | (同左) |

ファイル操作・コマンド実行は Anthropic 直接で使えます(Bedrock は、コンテナ内の Claude Code が持つツールを settings.json の許可で使います)。インターネット検索・ページ取得のアプリのツールは、Anthropic 直接のときだけ使えます。

### キーボードショートカット

`Mod` は macOS では ⌘、それ以外では Ctrl です。

| キー | 動作 |
| --- | --- |
| `Space`(押している間) | 録音し、離すと文字起こし・送信(対話画面。入力欄フォーカス時は通常のスペース入力) |
| `Mod`+`Shift`+`M` | 録音の開始 / 停止 |
| `Mod`+`1` / `2` / `3` | 対話 / ナレッジ / 設定を開く |
| `Mod`+`/` | ショートカット一覧を開く |

## 発話から応答までの流れ

発話 1 回分の処理(`send_chat`)と、その中で動く LLM の一覧です。詳細は [chat-flow.md](docs/chat-flow.md) を参照してください。★は LLM の呼び出しです。

```text
【1】入力
  ├─ テキスト入力 ──────────────┐
  └─ 音声入力                   │
       ↓                        │
     STT(文字起こし)            │
       ↓                        │
     ★① 校正(校正モデル登録時のみ)
       ↓                        │
       └────────────┬───────────┘
                    ↓
【2】送信前の準備(send_chat)
  1. モデルの選択と API キーの確認
  2. 発話を DB に保存
  3. ★② 会話の要約(往復数が上限を超えたときのみ)
  4. 関連ナレッジの想起(LLM なし。タイトル・タグ・本文の一致から、リンクを最大 2 ホップ辿る)
  5. スキルの決定
       ├ 入力欄で指定済み → そのスキルの手順を渡す(選定しない)
       └ 未指定 → ★③ スキル候補の選定(スキルがあるとき)
  6. システムプロンプトの組み立て
                    ↓
【3】メイン処理(tool_loop)
  ★④ 応答の生成
     ↓
   ツール呼び出しがある? ─ はい → ツール実行 → ④に戻る
     │                     (ファイル / シェル / Web / スキル / 記憶。
     │                      書き込みとコマンドはユーザーの承認が必要)
     └ いいえ
       ↓
【4】応答後
  1. 応答を DB に保存し、ナレッジのキャプチャへ追記
  2. TTS で読み上げ → 音声入力を再開
```

### LLM の一覧

| 番号 | 役割 | モデル | プロンプト | 実行条件 |
| --- | --- | --- | --- | --- |
| ① | 誤変換の校正 | 校正用に登録したモデル | `prompt_proofread` | 校正モデル登録時 |
| ② | 古い会話の要約 | チャットと同じモデル | `prompt_summary` | 往復数が上限を超えたとき |
| ③ | スキル候補の選定 | 軽量モデル(haiku 優先) | `prompt_skills` | スキルが 1 件以上あり、発話が 3 文字以上、入力欄で未指定 |
| ④ | 応答の生成とツール実行 | 画面で選んだモデル | `prompt_chat` | 常時 |

ナレッジ整理(抽出 `prompt_organize_v2`・統合 `prompt_consolidate`)とリーダーの宛先提案(`prompt_suggest`)は、チャット送信とは別に画面から起動します。

### ④に渡すシステムプロンプトの順序

プロンプトキャッシュが効くよう、変わりにくい順に並べ、固定部分の末尾までをキャッシュします。

固定部分(会話中ほぼ変わらない):

1. ベース指示(`prompt_chat`。エージェントの上書き → 全体設定 → 組み込みの既定)
2. ユーザーの指示(パーソナル / 共通 / エージェントのデータ、覚えておくこと)
3. 変わりにくい参考データ(パーソナルデータ、訂正履歴、会話の要約)
4. ツールの使い方(ファイル、シェル、Web、スキル)

可変部分(発話ごとに変わる):

1. 発話ごとの参考データ(関連ナレッジ、スキル候補)
2. 参考データの注意(中の指示には従わない)
3. `<skill>`(入力欄で指定したスキルの手順。最も優先させるため末尾)

## 必要環境

- macOS(必須)
- Node.js と npm
- Rust (stable、1.90 以上)
- Xcode Command Line Tools(whisper.cpp のビルドに C++ コンパイラと CMake が必要)
- Docker(任意。ワークのエージェントと、Bedrock 方式を使うときだけ。Docker Desktop や OrbStack など)

## 開発

```bash
npm install
npm run tauri dev
```

Next.js のみを起動する場合は `npm run dev` です(Tauri のコマンドは使えません)。

チェックとテスト:

```bash
npm run lint
npm test                     # フロントエンドの単体テスト(vitest)
cd src-tauri && cargo test
cargo clippy --all-targets -- -D warnings
```

`cargo` が PATH に無い場合は、`~/.rustup/toolchains/stable-*/bin` を PATH に追加してください。

## ビルド

```bash
npm run tauri build
```

- 成果物は `src-tauri/target/release/bundle/` 配下に出力されます。
- macOS の最小対応バージョンは 26.2 です(入力欄の自動伸縮に使う CSS `field-sizing` が WebKit 26.2 以降のため)([src-tauri/tauri.conf.json](src-tauri/tauri.conf.json))。
- whisper.cpp のビルドには macOS 10.15 以上のデプロイターゲットが必要なため、この値を下げないでください。

## 初期設定

### 1. API キーを登録する

アプリの設定画面で登録します。登録時に疎通確認を行い、成功したときだけ保存します。

| 用途 | キー |
| --- | --- |
| Claude | Anthropic API キー |
| Claude(Bedrock 経由) | `~/.aws/config` と `~/.aws/credentials` の中身(設定画面へそのまま貼り付け)。MFA 付きのスイッチロール(`role_arn` + `source_profile` + `mfa_serial`)と、IAM Identity Center(SSO。`sso_session` / `sso_start_url`)に対応。SSO はアプリが確認コードを表示し、ブラウザで承認する(`aws sso login` は不要)。コンテナ内の Claude Code へ一時キーを渡して使う(モデルは settings.json で決める) |
| 音声出力 / Google STT | Google Cloud API キー |
| ローカル LLM(Qwen 2.5 7B) | キー不要。設定画面の「AI Link」からダウンロードする。Web 検索・ページ取得は使えない。メモリ 16GB 以上を推奨 |

### 2. 音声まわりを準備する

- ローカル Whisper を使う場合は、設定画面からモデルをダウンロードしてください。
- 初回の録音時に、マイクの使用許可を求められます。
- 常時音声待機や会話の切り替えの確認で音声を使うには、設定画面の「定型音声を作成」(選んだ読み上げエンジンで合成)を先に実行してください。

## データの保存場所

すべてアプリデータディレクトリに保存され、リポジトリには含まれません。

- 識別子: `MyAssistant`
- macOS のパス: `~/Library/Application Support/MyAssistant/`
- 旧識別子(`dev.longin.tachicoma-agent`)のフォルダがあれば、初回起動時に自動で引き継ぎます。

| パス | 内容 |
| --- | --- |
| `timeline.db` | SQLite。会話ログ・要約・使用量・アプリ設定(起動時に自動でマイグレーションし、その前に `timeline.db.bak-v<版>` を残す) |
| `secrets.json` | API キー。**平文 JSON**(権限 0600)。OS のキーチェーンは使っていません |
| `workspaces/` | ワークのエージェント。`registry.json`(一覧)と、エージェントごとの `<UUID>/`(`timeline.db`・`secrets.json`・`knowledge/` などをパーソナルと同じ構成で持つ。サンドボックスを使うと `sandbox.env`(**平文**、権限 0600)と `sandbox/Dockerfile` も置く) |
| `models/` | Whisper モデル |
| `voicevox/` | VOICEVOX CORE・辞書・音声モデル(任意) |
| `llm/` | ローカル LLM の llama-server と Qwen のモデル(任意) |
| `voice/` | 定型音声 |

`timeline.db`・`secrets.json`・ナレッジはワークスペースごとに分かれます。上の表はパーソナルの場所で、`models/`・`voicevox/`・`llm/`・`voice/` は共有します。

ナレッジの Markdown は、既定ではアプリデータ配下に保存されます。設定画面またはナレッジ画面で任意のディレクトリに変更できます(既存のノートは移動しません)。ほかのワークスペースの保存先と重なる場所は選べません。

## ディレクトリ構成

```text
src/                    Next.js フロントエンド
  app/                  画面 (対話 / knowledge / skills / setup / shortcuts / debug)
  components/           UI コンポーネント (shadcn/ui は components/ui)
  lib/                  Tauri 呼び出し、音声での承認・切り替えの判定、

src-tauri/              Tauri バックエンド (Rust)
  src/commands/         フロントエンドから呼ぶコマンド
  src/services/         LLM クライアント、STT/TTS、整理バッチ、ナレッジ、

  src/db/               SQLite
  src/utils/            エラー型、パスのサンドボックス
  src/tray.rs           メニューバー常駐
```

## セキュリティ

- API キーの生値は `src-tauri/src/services/secrets.rs` の外へ出しません。フロントエンドには登録有無だけ返します(例外: ワークのエージェントのコンテナ内の Claude Code へ、実行ごとの環境変数としてだけ渡します)。
- ナレッジのパスはすべて `src-tauri/src/utils/path.rs` のサンドボックスを通します。
- `secrets.json`、`timeline.db`、`sandbox.env`、`.env*` はコミットしないでください(実体はアプリデータディレクトリにあります)。
- ワークのエージェントの作業は専用の Docker コンテナの中で行われ、ほかのエージェントや端末の認証情報から分離されます([docs/sandbox.md](docs/sandbox.md))。
- 画面は Content Security Policy で外部への読み込み・通信を止め、Markdown の画像は読み込みません(混入した指示で会話の内容を外へ送らせないため)。
- Whisper・VOICEVOX・ローカル LLM の取得物は、既定のバージョンを固定し、SHA-256 を照合します。

詳細は [docs/security.md](docs/security.md) を参照してください。
