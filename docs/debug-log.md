# デバッグモード

問題の調査のため、API の通信と文字起こしを記録するモード。**既定は無効**。実装は `services/debug_log.rs`、`commands/debug.rs`、設定の Debug Mode、画面は `src/app/debug/page.tsx`。

## 記録

有効な間、ナレッジ配下の `debug-logs/` へ、日付ごとの JSON Lines(`YYYY-MM-DD.jsonl`)で追記する。1 行 = 1 件。

```json
{ "time": "2026-10-29T13:14:15+09:00", "kind": "api", "data": { "api": "anthropic", "url": "...", "request": {...}, "status": 200, "response": {...} } }
```

| `kind` | 内容 | 記録元 |
| --- | --- | --- |
| `api` | API の 1 往復(`api` 名、URL、リクエスト、ステータス、レスポンス)。`api` は `anthropic` / `openai` / `google_tts` / `google_stt` / `aqua_stt` | `llm_client.rs`、`tts.rs`、`stt_google.rs`、`stt_aqua.rs` |
| `transcription` | 音声認識の結果(エンジン、言語、秒数、語彙ヒント、文字起こし)。VAD で発話なしと判定して認識を省いた場合は、その理由 | `commands/voice.rs` |

- API キーはヘッダーにのみ載るため、本文には含まれない。
- 音声データなど長大な base64 の値は、サイズだけ残して置き換える(`redact_at`)。
- 応答本文が JSON として読めなければ、文字列のまま記録する。
- 失敗した LLM リクエスト(ネットワークエラーなど)も、ステータス 0 で記録する。
- **無効なときは何もしない**。書き込みに失敗しても本来の処理は止めない(警告ログのみ)。

## 出力先の決定

- 出力先ディレクトリは、プロセス内のグローバル(`LOG_DIR`)に保持する。有効なときだけ値が入る。
- 次のときに `refresh` で決め直す: 起動時、デバッグモードの切り替え、ナレッジの保存先の変更、設定のインポート。
- ナレッジの保存先を変えると、ログの出力先も追従する(既存のログは移動しない)。

## 画面(`/debug`)

- デバッグモードが有効なときだけナビゲーションに「デバッグ」が出る。無効のときにページを開くと設定画面へ戻る。
- 日付ごとのログファイル一覧(新しい日付が先頭)、ログの読み込み、種類(すべて / API / 文字起こし)での絞り込み。新しい行が上。
- 壊れた行は捨てず、本文をそのまま表示できる形で残す。
- ログの削除: 1 ファイル、またはすべて。確認ダイアログを出す。
- ログが大きい場合は、新しい側の 5MB だけを行の区切りから読む。
- ログファイルとして扱う名前は `YYYY-MM-DD.jsonl` の形だけ(パスの指定でほかのファイルを読み書きできないようにする)。

## 取り扱いの注意

ログには会話の内容(発話・応答・ナレッジの断片)がそのまま含まれる。ナレッジを同期・共有している場合、`debug-logs/` も同じ場所に置かれる。調査が済んだらモードを切り、ログを削除すること。
