# アプリ全体のバックアップとリストア

全エージェントの会話・設定・ナレッジ・API キーを 1 つの zip に書き出し、復元する。パスワードは任意(`services/backup.rs`、コマンドは `commands/backup.rs`)。画面は全体設定の「アプリ」タブ(App Backup)。設定だけの書き出しは [data-and-settings.md](data-and-settings.md) と [global-settings.md](global-settings.md) を参照。

## アーカイブの中身

| パス | 内容 |
| --- | --- |
| `manifest.json` | アプリ名・形式の版(`FORMAT_VERSION`)・作成日時・DB の最新の版・ワークスペース一覧・ファイルごとの SHA-256 |
| `shared/registry.json`, `shared/global_settings.json` | エージェント一覧、全体設定(プロキシの一覧と既定を含む) |
| `shared/proxy-secrets.json` | 通信のプロキシのパスワード(平文のまま。`proxy/secrets.json`)。リストアでは、含まれているときだけ差し替える(古いバックアップなら、いまのパスワードを残す) |
| `shared/kept-knowledge/` | エージェント削除時に残したナレッジ |
| `ws/<id>/timeline.db` | DB のスナップショット(`VACUUM INTO`) |
| `ws/<id>/secrets.json`, `ws/<id>/tts_dictionary.json` | API キー(平文のまま)、読み上げ辞書 |
| `ws/<id>/knowledge/` | ナレッジ。保存先がアプリデータの外でも含める。`.` 始まりのフォルダ(コマンド権限 `.my-assistant/command-policy.json`)と、スキル(`Skills/`)も含む。直下の `data/`(サンドボックスの担当システムのフォルダ)は含めない |

`<id>` は `personal`・`leader`・エージェントの UUID。`models/`・`voicevox/`・`voice/`、`-wal`/`-shm`、`.bak-vN` は含めない。シンボリックリンクと、名前が UTF-8 でないファイルは取り込まない。

## バックアップ

0. パスワードを指定した場合は、すべてのエントリ(manifest を含む)を AES-256(WinZip AES)で暗号化する。ファイル名は暗号化されない。空のパスワードは「指定なし」。
1. 各ワークスペースの DB を、別の読み取り接続から `VACUUM INTO` でアプリデータ内の一時フォルダへ複製する(稼働中の DB を生コピーしない)。
2. 複製した DB から `knowledge_dir` を読み、設定があればその場所を、なければ `<ワークスペース>/knowledge` を取り込む。アプリデータ全体を含んでしまう保存先は取り込まない(警告のみ)。
3. `<出力>.zip.part` へ書いてからリネームする。出力ファイルは所有者のみ読める権限(0600)にする。

## リストア

1. **準備**(`restore_prepare`): zip を `restore-staging/` へ展開する。現在のデータには触れない。
   - 暗号化されていてパスワードが無い・違うときは、専用のエラー(`backup_password_required` / `backup_password_wrong`)を返し、画面がパスワードを求める。暗号化されていない zip では、パスワードは使われない。
   - manifest の検証: アプリ名、形式の版、DB の版が現行以下、ワークスペース ID の文字種、`personal` の存在。
   - 各エントリは許可した場所(上表)の安全な相対パスだけ。`..`・絶対パス・バックスラッシュ・未知の場所は拒否する(zip-slip 対策)。manifest に載っていないエントリは展開しない。
   - 展開する合計の大きさは 64GB まで(展開すると巨大になる細工された zip でディスクを埋めさせない)。
   - 展開しながら SHA-256 を照合し、展開した DB に `PRAGMA quick_check` と版の確認をする。失敗したら展開先を消す。
2. **確認と再起動**(`restore_apply`): 画面で確認を取り、予約(`pending-restore.json`)を書いてアプリを再起動する。取り消したら `restore_discard` で展開先を消す。
3. **差し替え**(`apply_pending`): 次回起動の、DB を開く前(`lib.rs` の `setup` 冒頭)に行う。
   - 現在のパーソナルのファイルと `workspaces/` を `restore-backup-<日時>/` へ移動する(退避)。
   - 展開済みの内容を所定の場所へ移動する。
   - 各 DB の `knowledge_dir` を消す(ナレッジは標準の位置へ戻したため)。
   - 途中で失敗したら、置いたものを消して退避から元に戻し、通常どおり起動する。予約は先に消すので、失敗を繰り返さない。

## 決定事項

- API キーは平文のまま含める(アプリ内の保存と同じ扱い)。zip は 0600 で書き出す。パスワードを設定すると zip 全体を暗号化できる(任意。必須にしない)。パスワードはアプリに保存せず、この画面の状態と Tauri コマンドの引数にだけ置く。
- 暗号化は AES-256 にする。ZipCrypto は弱いため使わない。
- ナレッジの保存先がアプリデータの外でも、中身はアーカイブに含める。復元は常に標準の位置へ戻し、カスタムの保存先の設定は解除する。元のフォルダには触れない。
- 復元は再起動時の差し替えにする。DB の接続と実行中の処理(会話・整理・作業)が残るアプリ内で、ファイルを入れ替えない。
- 現在のデータは削除せず、`restore-backup-<日時>/` に残す。不要になったら手動で消す。

## 既知の限界

- AES-256 の zip は macOS 標準のアーカイブユーティリティでは開けない(7-Zip・Keka などが必要)。アプリでの復元には影響しない。
- パスワードを忘れると復元できない。パスワードの強度や長さは検査しない(確認欄との一致だけ)。
- 暗号化しても、zip 内のファイル名(ワークスペース ID・ナレッジのファイル名)は見える。
- バックアップ中も整理バッチなどは止めない。DB は一貫しているが、ナレッジのファイルは取り込み中に更新されることがある。
- 他の端末へ復元すると、カスタムのナレッジ保存先は標準の位置になる。
- モデル類(Whisper・VOICEVOX)は含めないため、復元後に必要なら取得し直す。
- 新しいバージョンのアプリで作ったバックアップは読み込めない。
- 差し替えに失敗しても画面には出ない(ログに残る)。データは元のまま起動する。
