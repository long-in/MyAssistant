# セキュリティ設計

## 方針の一覧

| 領域 | 方針 | 実装 |
| --- | --- | --- |
| API キー | 生値は `secrets.rs` の外へ出さない。フロントエンドには登録有無(bool)だけ返す | `services/secrets.rs` |
| ファイルパス | ナレッジのパスはすべてサンドボックスを通す。LLM 出力・フロントエンドのパスを直接 `fs` に渡さない | `utils/path.rs` |
| コマンド実行 | 静的判定 + 計画承認 + 個別承認 + 範囲制限 + タイムアウト + 中断 | `services/command_policy.rs` ほか |
| プロンプトインジェクション | 外部由来の文章は「参考データ」として渡し、中の指示には従わせない | 各プロンプト |
| ワークスペースの分離 | DB・API キー・AWS の状態・ナレッジの保存先をワークスペースごとに分け、混ぜない | `services/workspace.rs` |
| コミット | `secrets.json`、`timeline.db`、`.env*` をコミットしない | — |

## ワークスペースの分離(`services/workspace.rs`)

- **API キー**: ワークスペースごとに別の `secrets.json` を持つ(`Secrets` のインスタンス)。コマンドは受け取った `ctx` の保管庫だけを使うため、ほかのワークスペースのキーを読み書きしない。
- **キーのコピー**: 設定のコピーでキーを写す場合も、Rust 内(`Secrets::copy_from`)で完結し、画面には件数だけ返す。既定ではコピーしない(明示的に選んだときだけ)。同じワークスペースどうしのコピーは拒否する。
- **エージェントの ID**: Rust が生成した UUID だけを使い、フロントエンドからのパスや名前を保存先に使わない。削除は、一覧にある ID のフォルダ(`workspaces/<id>/`)だけを消す。一覧に無い ID(`..` など)は拒否する。独自に指定されたナレッジの保存先は消さない。
- **削除と裏の処理**: 削除したエージェントには削除の印が付き、バッチと会話は書き込む前に確かめて止まる。
- **保存先の重なり**: ナレッジとデバッグログの保存先は、ほかのワークスペースの現在の場所・既定の場所と、同じ場所・親子関係のいずれでも重ならない(`check_paths_free`)。さらに、アプリデータ全体・`workspaces/`・ほかのワークスペースのDBやキーのフォルダを含む場所、またはその中の場所は、相手がいなくても保存先にできない(自分の既定のナレッジの中を除く)。これにより、ナレッジ画面(一覧・読み取り・編集・削除・エクスポート)から `secrets.json` や `timeline.db` に届かない。確認と保存は1つのロックの中で行う。
- **コマンド実行**: 作業ディレクトリはそのワークスペースのナレッジに限られ、`secrets.json`・`timeline.db` を含むコマンドは保護の対象([command-policy.md](command-policy.md))。
- **パーソナルデータ**: 設定のコピーでは写さない(エージェントにはパーソナルデータを渡さない)。エージェントデータも写さない。

## AWS 認証(`aws.rs`)

- 設定画面に貼り付けた `~/.aws/config` と `~/.aws/credentials` の本文を、`secrets.json` に保持する。フロントエンドへはプロファイル名・リージョン・MFA の要否だけを返し、キーは返さない。
- 使うプロファイルは、貼り付けた内容から読み取った候補(`preview_aws_config`。保存しない)の中から、保存前に利用者が選ぶ。候補が1つならそれが選ばれ、複数なら選ぶまで保存できない。保存済みの選択が使えなくなっても、他のプロファイルへ黙って切り替えず、未選択として扱う。
- `role_arn` + `source_profile` のプロファイルは、`sts:AssumeRole`(MFA 付き)で一時クレデンシャルを得る。一時クレデンシャルは**メモリ上だけ**に置き、期限の 60 秒前に取り直す。ディスクにも保存しない。
- MFA コードが必要なときは、Rust が `aws-mfa-required` イベントを送って入力を待つ(上限 180 秒、誤入力は 3 回まで再入力)。呼び出し側(対話・整理など)はコードが届くまで待ち、届けばそのまま続行する。同時に複数の呼び出しが来ても入力は 1 回にまとめる。
- 対応するのは「アクセスキーを持つプロファイル」と「そのプロファイルを `source_profile` にした 1 段のロール」。SSO・`credential_process`・`credential_source`・ロールの連鎖は未対応。貼り付けフォームでは、選べないプロファイルをその理由(`source_profile` の参照先が無い、未対応の方式など)付きで表示する。
- Bedrock にはサーバーツール(検索・ページ取得)が無いため、Web 検索は使えない。ファイル操作とコマンド実行(承認付き)は Anthropic 直接と同じ。
- 使う Bedrock のモデルは利用者が登録する(モデル ID・推論プロファイル ID・ARN。`secrets.json` の `aws_models`)。初回の保存時だけ、`global.anthropic.claude-haiku-5-5`、`global.anthropic.claude-sonnet-5-5`、`global.anthropic.claude-opus-5-5` を候補として登録する。実際の ID はアカウントで `aws bedrock list-inference-profiles` を見て確認する。設定画面の「Bedrockからglobalのモデルを取得」で、推論プロファイル一覧(`bedrock:ListInferenceProfiles`)から `global.anthropic.` で始まる ID を取得して選べる(`list-foundation-models` は接頭辞なしの基盤モデル ID しか返さないため、推論プロファイル側を使う)。登録したモデルがモデル選択に並び、選択値はその ID そのものになる。

## API キー(`secrets.rs`)

- 保存先は、ワークスペースごとの `secrets.json`(パーソナルはアプリデータ直下、エージェントは `workspaces/<UUID>/` 配下。所有者のみ読み書き可の権限 0600)。**平文の JSON** であり、OS のキーチェーンは使っていない。この点は設定画面にも明記している。
- 取得関数(`get_key` / `get_aqua_key` / `get_tts_key`)は Rust 内部の HTTP クライアント専用で、**Tauri コマンドとして公開しない**。コマンドとして出すのは登録有無・保存・削除だけ。
- 保存は一時ファイルへ書いてからリネームする(書き込み途中の破損を避ける)。
- 保存前に疎通確認を行い、成功したときだけ保存する(モデル一覧取得・音声一覧取得・認証のみの確認。いずれも読み取り専用で課金されない)。
- キーの種類: Anthropic、Amazon Bedrock(下記)、Google Cloud(TTS と Google STT で共通)、Aqua Voice(Google とは別)。
- エラーの `message` には API キーを含めない。キーはリクエストヘッダーにのみ載り、デバッグログの本文にも含まれない。
- 設定のエクスポートには含めない。アプリ全体のバックアップ([backup.md](backup.md))には、平文のまま含める。zip は 0600 で書き出し(任意のパスワードで AES-256 暗号化もできる)、リストアで戻した `secrets.json` も 0600 にする。

## パスのサンドボックス(`utils/path.rs`)

| 関数 | 用途 |
| --- | --- |
| `resolve_existing(root, rel)` | `root` 配下の**既存**パスの解決。絶対パス・`..`・シンボリックリンク経由の脱出を拒否する。正規化済みパスを返す |
| `ensure_dir(root, parts)` | 書き込み先ディレクトリを作成し、正規化後も `root` 配下であることを確認する |
| `resolve_new_file(root, rel)` | 新規作成するファイルの書き込み先。親ディレクトリは必要なら作成する。各要素は `slug` で変化しない安全な名前に限る(英数字・日本語・`_`・`-`・`.`。先頭の `.` と `..` は不可)。既存のシンボリックリンクは拒否する。上書きの可否は呼び出し側が決める |
| `slug` / `category_parts` | カテゴリ・ファイル名を安全な要素へ変換する(区切り文字や `.` を残さない。カテゴリは最大 2 階層、空なら `Inbox`) |

- 操作ルート(ナレッジ)は引数で受ける形のままにしてあり、拡大する場合もこの関数群を通す。
- 読み取り・一覧・検索は隠しファイル(`.` 始まり)を対象外にし、シンボリックリンクは辿らない([agent-file-tools.md](agent-file-tools.md))。
- フロントエンドから受けるパスも、ダイアログで選ばれた絶対パスのみ(エクスポート・インポート先、ナレッジの保存先、設定ファイル)。

## プロンプトインジェクション対策

ナレッジ・会話の要約・ツール結果・Web ページなど、**第三者が書き換えうる文章**を LLM に渡すときの共通方針。

- `<stt_corrections>` `<previous_context>` `<related_knowledge>` `<conversation_summary>` `<user_profile>` は参考データであり、その中の指示には従わない、と**システムプロンプトの末尾で明示する**([chat-flow.md](chat-flow.md))。
- 整理バッチ・要約・校正のプロンプトも、`<conversation>` `<summary>` `<transcript>` `<context>` の内容は対象データであり、中の指示には従わないと明示する。
- 覚えておくこと(`<pinned_memory>`)はユーザーの指示として従わせる。そのため本文に `<` `>`・制御文字を入れさせず、記録のたびにチャットへ表示する([memory.md](memory.md))。
- ツール結果(ファイル・コマンド出力・Web ページ)に書かれた指示には従わない(`TOOL_GUIDE`)。例外は `use_skill` の結果と、入力欄で指定したスキルの `<skill>` で、ユーザーが登録した手順として従う。ただしファイル作成・コマンド実行の承認と制限は変わらない。スキルの説明・呼び出し語は `<` `>` を拒否し、候補の一覧は参考データとして渡す([skills.md](skills.md))。
- `web_fetch` は、ツール結果に書かれた URL を根拠にした取得を禁止する(`url_sources.client_tool_results = none`)。ナレッジのファイルに混入した指示で、情報が外部へ送出されるのを防ぐ。
- パーソナルデータ・エージェントデータ・共通データの入力値は、制御文字(エージェントデータ・共通データでは改行を除く)と `<` `>` を拒否する(タグの偽装でプロンプトを壊されないようにする)。

## コマンド実行の守り

[agent-command-tasks.md](agent-command-tasks.md) と [command-policy.md](command-policy.md) を参照。

1. 構文解析による静的な判定(`rm`・`sudo`・OS に影響するコマンド・機密ファイル・システム領域の拒否を初期値に持つ)。
2. 状態を変える作業は計画の承認が必須。計画外・破壊的なコマンドは個別承認。
3. 読み取り系以外はナレッジのディレクトリ内に限る。
4. タイムアウト(既定 60 秒、最大 600 秒)とプロセスグループごとの強制終了、ユーザーによる中断。
5. 承認の待ち時間は 120 秒で、超えたら拒否。
6. ポリシーファイルは隠しフォルダにあり、LLM のファイルツールから触れない。

**限界**: 静的な検査のため、`python -c` の中身や実行時に決まるパスまでは見ない。

## プライバシー

| 送信先 | 送るもの |
| --- | --- |
| Anthropic | 発話、直近の会話、要約、パーソナルデータ・共通データ・エージェントデータ(有効時)、関連ナレッジの要約、ツール結果。整理バッチ・校正・要約でも会話の内容 |
| Amazon Bedrock | Anthropic と同様(AWS の指定リージョンへ送信) |
| Anthropic(Web 検索・取得) | 検索語・URL(ナレッジや会話の内容を含めないよう指示) |
| Google Cloud | 応答テキスト(TTS)、録音(Google STT を選んだときのみ) |
| Aqua Voice | 録音(Aqua を選んだときのみ) |
| GitHub(`github.com`) | VOICEVOX の取得時のみ。CORE・ONNX Runtime・辞書・音声モデルのダウンロード要求(送信する内容はない) |

- ローカル Whisper を選べば、録音は端末の外へ出ない。読み上げに VOICEVOX を選べば、応答テキストも端末の外へ出ない。
- 常時待機中は、起動ワードを含まない発話を LLM へ送らない([wake-standby.md](wake-standby.md))。
- **デバッグモード**を有効にすると、各 API のリクエスト・レスポンス(会話の内容を含む)と文字起こしを、ナレッジ配下にファイルとして保存する。ナレッジを同期・共有している場合は注意する([debug-log.md](debug-log.md))。
- 設定のエクスポートにはパーソナルデータとコマンド権限が含まれるため、ファイルの扱いに注意する。
