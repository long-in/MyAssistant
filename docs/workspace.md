# ワークスペース

パーソナルと、ワークの複数プロジェクトを、完全に分けて使う機能です。

- **パーソナル**: 従来のエージェント。保存場所は変えていません(アプリデータ直下)。
- **ワーク**: 仕事用。最大30件のプロジェクトを作れます。各プロジェクトは独立したエージェントで、名称とイメージカラーを持ちます。

## 保存場所

| 対象 | 場所 |
| --- | --- |
| パーソナル | `<アプリデータ>/timeline.db`、`secrets.json`、`knowledge/`(従来どおり) |
| プロジェクト | `<アプリデータ>/workspaces/<UUID>/` に同じ構成 |
| プロジェクト一覧 | `<アプリデータ>/workspaces/registry.json`(id・名称・色・作成日時) |

分離するもの: 設定・プロファイル・会話・使用量(`timeline.db`)、APIキー・AWS設定(`secrets.json`)、ナレッジ、コマンドポリシー、デバッグログ、聞き取り訂正、読み上げ辞書。

共有するもの(端末の資源): Whisper・VOICEVOX・VAD のモデルとエンジン、録音、定型音声(`voice/`)。

## 構成(`services/workspace.rs`)

- `WorkspaceCtx`: 1ワークスペース分の状態(`db`・`secrets`・`aws`・`batch`)。
- `Workspaces`: 読み込み済みの ctx、選択中の ID、プロジェクト一覧。プロジェクトを読み込むのは、切り替えたとき・作ったときだけ。バッチや保存先の確認のためには、一時的に開いて使い終わったら捨てる(`open_for_batch`)。
- `Shared`: 同じワークスペースを別々に開いた ctx の間で共有する状態(整理バッチの多重実行ガード・削除の印)。一時的に開いたものと読み込み済みのものが、同じバッチを二重に動かしたり、削除に気づかなかったりしない。
- コマンドは `ctx: Ctx` で選択中のワークスペースを受け取る。処理の途中で切り替わっても、受け取った ctx を使い続けるため混線しない。
- 定期バッチ(`services/scheduler.rs`)は、ワークスペースごとの間隔で独立して動かす。終了時のバッチは、開いているワークスペースだけを対象にする。

## 画面

- 左メニュー上部で、Personal / Work を切り替え、ワークではプロジェクトを選ぶ(`WorkspaceSwitcher`)。畳んだ状態でも、色の丸からプロジェクトを選べる。
- macOS のメニューバーとトレイにも「Projects」があり、Personal と各プロジェクトへ直接切り替えられる。トレイの先頭には、いまのワークスペースを表示する。
- ワークスペース関連の表記は英語に固定する(ナビゲーション・メニューバーに合わせる)。
- プロジェクトの色は、メニュー上部のロゴ、画面上端の細い帯、対話画面右上のバッジ(`WorkspaceBadge`)に出る。
- `/workspace` でプロジェクトを作成・編集・削除し、設定をコピーする。作成するとそのプロジェクトを選択状態にする(画面は `/workspace` のまま。続けて設定のコピーができる)。
- 切り替えると、対話画面は作り直され(読み上げ・録音・常時待機が止まる)、切替先でAPIキーの有無を確かめる。会話のセッションはワークスペースごとに保持し、戻ると同じ会話の続きになる。

## 設定のコピー

`/workspace` の「設定のコピー」で、パーソナルまたはプロジェクトの設定を、別のワークスペースへ写す(`copy_workspace_settings`、`settings_transfer::copy`)。コピー元は変更しない。

- 対象: 設定のエクスポートと同じ項目(モデル・音声・起動ワード・調整値・整理バッチなど)とコマンド権限。
- 既定ではコピーしないもの: APIキー・AWS設定(スイッチ「APIキーもコピーする」)、パーソナルデータ(スイッチ「パーソナルデータもコピーする」)。パーソナルデータは仕事用へ持ち込まないのが通常のため、別のスイッチにしている。
- キーの生値はRust内(`Secrets::copy_from`)で写し、画面には件数だけ返す。キーを写したら、コピー先のAWS一時クレデンシャルは破棄する。
- 設定の検証に失敗したら、設定もキーも何も書かない。同じワークスペースどうしのコピーは拒否する。
- コピー先は選択中のワークスペースが既定。コピー先が選択中のときは、設定画面を読み直す。実行前に確認ダイアログを出す(コピー先の同じ項目は上書き)。

## 保存先の分離

ナレッジとデバッグログの保存先は、ワークスペース(パーソナルとすべてのプロジェクト)の間で重ならない。
- 保存先を変えるとき(`set_knowledge_dir`、`set_debug_log_dir`、「既定に戻す」を含む)、他のワークスペースの保存先と照合する(`Workspaces::ensure_paths_free`)。重なれば `path_in_use` で拒否し、何も保存しない。
- 照合の相手は、他のワークスペースの現在の保存先と既定の保存先の両方で、ナレッジとデバッグログが対象。既定も含めるのは、相手が「既定に戻す」ときに衝突しないようにするため。
- 重なりは、同じ場所と、親子関係(含む・含まれる)の両方。まだ存在しない場所もシンボリックリンクを解決して比べる。プロジェクトのデータのフォルダ(`workspaces/<id>/`)や、アプリデータ全体を含む場所も、これで拒否される。
- **アプリのデータは保存先にできない**: アプリデータ全体・`workspaces/`・ほかのワークスペースのDBやキーのフォルダを含む場所、またはその中の場所は、相手のワークスペースが無くても拒否する(自分の既定のナレッジの中だけは可)。これを外すと、ナレッジ画面から `secrets.json` や `timeline.db` を読み書きできてしまうため。
- プロジェクトの作成時にも、既存のワークスペースの保存先が新しいプロジェクトのフォルダを含んでいないかを確かめる(古い設定でアプリデータ全体を保存先にしている場合は、作成を拒否する。保存先を変えてから作る)。
- 保存先の確認から保存までは、他の保存先の変更・削除と交差しないよう、1つのロックの中で行う(`set_location`)。
- 自分自身の保存先とは重なってよい(デバッグログの既定はナレッジの中)。
- 設定のコピーは、ナレッジの保存先(`knowledge_dir`)・デバッグログの保存先(`debug_log_dir`)を対象にしない。ナレッジ本体もコピーしない。

## 決定事項

- プロジェクト名は1〜40文字(制御文字なし)。上限は30件。
  - 「パーソナル」「ワーク」「Personal」「Work」は予約名で、プロジェクト名にできない(大文字小文字・前後の空白は無視。これらを含むだけの名称は可)。
  - 名称もプロジェクト同士で重複禁止。前後の空白を除き、大文字小文字を区別せず比較する(作成・更新とも拒否、削除すると空く)。
- イメージカラーは、あらかじめ用意した30色(`PALETTE`)から選ぶ。自由な色は選べない。
  - プロジェクト同士で色の重複は禁止(作成・更新とも拒否、削除すると空く)。上限と同数なので、必ず空き色がある。
  - パレットは Rust(`services/workspace.rs`)を唯一の定義とし、画面は `list_project_colors` で取得する。
  - 使用中の色は、画面で選べない表示にする。新規作成時は、空いている先頭の色が選ばれている。
- プロジェクトの削除は、アプリが管理するフォルダ(`workspaces/<id>/`)をすべて消す(会話・設定・APIキー・既定の場所のナレッジ)。利用者が独自に指定したナレッジの保存先は消さない。元に戻せないため確認を取る。
  - 裏で動いている整理バッチ・会話は、削除の印を見て、書き込む前に止まる(削除後にフォルダやファイルを作り直さない)。
  - 切り替え・読み込み・作成・更新・削除は1つのロックで直列にし、削除と交差しても、削除済みのプロジェクトを選択・読み込みしない。選択中の ctx が見つからないときは、パニックせずパーソナルへ戻す。
- デバッグログの出力先・有効/無効は、ワークスペースごとの状態(`WorkspaceCtx.debug`)として持つ。選択を切り替えても、裏で動くワークスペースのログは自分のワークスペースにだけ書かれる。
- MFA コードの入力要求には、求めているワークスペース(名称と色)を載せ、コードはそのワークスペースへ返す。選択中とは限らない裏のプロジェクトが求めても、入力欄でどのプロジェクトか分かり、正しい相手へ届く。複数が同時に求めたら、順に出す。AWS の一時認証と MFA 待ちは、同じワークスペースを開き直した ctx の間で共有する(`Shared`)。
- Bedrock のモデル一覧は秘密ではない設定項目なので、キーをコピーしないときも写す(AWS の認証情報は写さない)。
- 設定のコピーは、検証 → キー → コマンド権限 → 設定(トランザクション)の順に書き、途中で失敗したらキーとコマンド権限を元へ戻す。コピー先が選択中なら、失敗しても表示を更新する。
- 聞き取り訂正のキャッシュ(`SessionContexts`)は、ワークスペースとセッションの組で持つ。訂正の追加はそのワークスペースの分だけ、プロジェクトの削除はその分を捨てる。
- 一覧ファイルが壊れていたら`registry.json.corrupt`へ退避して空から始める。プロジェクトのフォルダは消さない。

## 未対応・要判断

最終判断のために、現時点で未対応のものをまとめています。

| 項目 | 現状 | 影響 |
| --- | --- | --- |
| 設定のコピーの対象外 | 読み上げ辞書、ナレッジ、会話、ナレッジの保存先(`knowledge_dir`)はコピーしない | 辞書はプロジェクトごとに登録し直す。コピー先のナレッジの保存先は既定のまま |
| キーのコピーは上書き方式 | コピー先にだけあるキーは残し、同じキーは上書きする(コピー元にあるキーは、削除の同期はしない) | コピー元でキーを削除しても、コピー先には残る |
| 切り替え時の実行中の依頼 | **仕様は決定済み・未実装**。切り替えても止めず、承認が要るときは回答を待ち、そのワークスペースへ戻ったら、回答して再開する。現状は、承認のダイアログが出ないため120秒で自動拒否される | 承認が要る作業は、切り替えると実質失敗する。許可済みの操作だけは進む |
| 実行中の依頼の中断スロット | `AgentState` がグローバルで、中断は1件分 | 切り替えた先で新しい依頼を始めると、裏の依頼を「中断」で止められない |
| 関連ノートのキャッシュ | `GraphCache` はグローバルで1件分(ルートのパスで識別) | 動作上は混ざらない。切り替えのたびに作り直す |
| 削除時の実行中のツール | 整理バッチ・会話の保存は削除の印で止まるが、エージェントが実行中のファイル操作・コマンドは、その場では止まらない | 削除の直前に始めた依頼のファイル操作が、削除と交差して数件残る可能性がある(既定の場所のフォルダは削除で消える) |
| 常時待機 | 切り替えで対話画面を作り直すため止まる。切替先で待機設定がオンなら再開する想定だが、実機では未確認 | 再開しない場合は、対話画面でマイクを入れ直す |
| 終了時のバッチ | 開いているワークスペースだけが対象 | 未起動のプロジェクトの未処理ログは、次回の定期バッチまで残る |
| ショートカット | ワークスペースの切り替えのキーボードショートカットは無い | 切り替えは、画面・メニューバー・トレイから行う |
| パーソナルの既存の保存先 | パーソナルがすでに独自のナレッジの保存先(例: Obsidian の vault)を使っている場合、その場所はプロジェクトから選べない | 意図どおり。重ねたい場合は、保存先の重なり禁止を緩める必要がある |
| 実機での確認 | Rustは `cargo test`、フロントは lint・型・静的ビルドまで。画面の実機確認(切り替え、音声、色の表示、レイアウト)は未実施 | 実機で確認が必要 |
