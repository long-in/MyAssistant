# ワークスペース

パーソナルと、ワークの複数スペースを、完全に分けて使う機能です。

- **パーソナル**: 従来のエージェント。保存場所は変えていません(アプリデータ直下)。
- **ワーク**: 仕事用。最大30件のスペースを作れます。各スペースは独立したエージェントで、名称とイメージカラーを持ちます。

## 保存場所

| 対象 | 場所 |
| --- | --- |
| パーソナル | `<アプリデータ>/timeline.db`、`secrets.json`、`knowledge/`(従来どおり) |
| スペース | `<アプリデータ>/workspaces/<UUID>/` に同じ構成 |
| スペース一覧 | `<アプリデータ>/workspaces/registry.json`(id・名称・色・作成日時) |

分離するもの: 設定・プロファイル・会話・使用量(`timeline.db`)、APIキー・AWS設定(`secrets.json`)、ナレッジ、コマンドポリシー、デバッグログ、聞き取り訂正、読み上げ辞書。

共有するもの(端末の資源): Whisper・VOICEVOX・VAD のモデルとエンジン、録音、定型音声(`voice/`)。

## 構成(`services/workspace.rs`)

- `WorkspaceCtx`: 1ワークスペース分の状態(`db`・`secrets`・`aws`・`batch`)。
- `Workspaces`: 読み込み済みの ctx、選択中の ID、スペース一覧。スペースを読み込むのは、切り替えたとき・作ったときだけ。バッチや保存先の確認のためには、一時的に開いて使い終わったら捨てる(`open_for_batch`)。
- `Shared`: 同じワークスペースを別々に開いた ctx の間で共有する状態(整理バッチの多重実行ガード・削除の印)。一時的に開いたものと読み込み済みのものが、同じバッチを二重に動かしたり、削除に気づかなかったりしない。
- コマンドは `ctx: Ctx` で選択中のワークスペースを受け取る。処理の途中で切り替わっても、受け取った ctx を使い続けるため混線しない。
- 定期バッチ(`services/scheduler.rs`)は、ワークスペースごとの間隔で独立して動かす。終了時のバッチは、開いているワークスペースだけを対象にする。

## 画面

- 左メニュー上部で、Personal / Work を切り替え、ワークではスペースを選ぶ(`WorkspaceSwitcher`)。畳んだ状態でも、色の丸からスペースを選べる。
- macOS のメニューバーとトレイにも「Spaces」があり、Personal と各スペースへ直接切り替えられる。トレイの先頭には、いまのワークスペースを表示する。
- ワークスペース関連の表記は英語に固定する(ナビゲーション・メニューバーに合わせる)。
- スペースの色は、メニュー上部のロゴ、画面上端の細い帯、対話画面右上のバッジ(`WorkspaceBadge`)に出る。
- `/workspace` でスペースを作成・編集・削除し、設定をコピーする。作成するとそのスペースを選択状態にする(画面は `/workspace` のまま。続けて設定のコピーができる)。
- 切り替えると、対話画面は作り直され(読み上げ・録音・常時待機が止まる)、切替先でAPIキーの有無を確かめる。会話のセッションはワークスペースごとに保持し、戻ると同じ会話の続きになる。

## 依頼の継続と再開

ワークスペースを切り替えても、実行中の作業の依頼(ファイル操作・コマンド)は止めない。承認が要るときは回答を待ち、そのワークスペースへ戻ったら、回答して再開できる。

- 依頼の進捗・承認待ち・結果は、ワークスペースごとに記録する(`services/agent_run.rs`の`AgentState`。進捗は新しい側の最大500件、メモリ上のみで、アプリを再起動すると消える。会話の本文はDBに残る)。
- 画面は、離れるとき `agent_detach` で接続を外し(依頼は止まらない)、戻ったとき `agent_resume` で状況を受け取って接続し直す。
  - 実行中なら、「処理中」の表示・進捗ログ・承認ダイアログを戻す。承認ダイアログが出れば、音声での返答の待ち受けも始まる。回答すれば、そのまま続く。
  - 離れている間に終わっていれば、結果をやり取りに加える。**自動では読み上げない**(戻った直後に話し出さないため)。
  - 戻った画面が受け取った続きの進捗と結果は、イベント(`finished`)で届く。最初の画面は、これまでどおりコマンドの戻り値で結果を受け取る(二重に受け取らない)。
- 承認待ちの時間切れ(120秒)は、そのワークスペースを選んでいる間だけ数える。裏にいる間は止まる。
- 画面を離れたあとに返答が届いても、読み上げたり、やり取りへ加えたりしない(結果は戻ったときに受け取る)。
- スペースを削除すると、そのスペースの実行中の依頼を中断する(動いているコマンドは強制終了、承認待ちは拒否)。

## 設定のコピー

`/workspace` の「設定のコピー」で、パーソナルまたはスペースの設定を、別のワークスペースへ写す(`copy_workspace_settings`、`settings_transfer::copy`)。コピー元は変更しない。

- 対象: 設定のエクスポートと同じ項目(モデル・音声・起動ワード・調整値・整理バッチなど)とコマンド権限。
- 既定ではコピーしないもの: APIキー・AWS設定(スイッチ「APIキーもコピーする」)、パーソナルデータ(スイッチ「パーソナルデータもコピーする」)。パーソナルデータは仕事用へ持ち込まないのが通常のため、別のスイッチにしている。
- キーの生値はRust内(`Secrets::copy_from`)で写し、画面には件数だけ返す。キーを写したら、コピー先のAWS一時クレデンシャルは破棄する。
- 設定の検証に失敗したら、設定もキーも何も書かない。同じワークスペースどうしのコピーは拒否する。
- コピー先は選択中のワークスペースが既定。コピー先が選択中のときは、設定画面を読み直す。実行前に確認ダイアログを出す(コピー先の同じ項目は上書き)。

## 保存先の分離

ナレッジとデバッグログの保存先は、ワークスペース(パーソナルとすべてのスペース)の間で重ならない。
- 保存先を変えるとき(`set_knowledge_dir`、`set_debug_log_dir`、「既定に戻す」を含む)、他のワークスペースの保存先と照合する(`Workspaces::ensure_paths_free`)。重なれば `path_in_use` で拒否し、何も保存しない。
- 照合の相手は、他のワークスペースの現在の保存先と既定の保存先の両方で、ナレッジとデバッグログが対象。既定も含めるのは、相手が「既定に戻す」ときに衝突しないようにするため。
- 重なりは、同じ場所と、親子関係(含む・含まれる)の両方。まだ存在しない場所もシンボリックリンクを解決して比べる。スペースのデータのフォルダ(`workspaces/<id>/`)や、アプリデータ全体を含む場所も、これで拒否される。
- **アプリのデータは保存先にできない**: アプリデータ全体・`workspaces/`・ほかのワークスペースのDBやキーのフォルダを含む場所、またはその中の場所は、相手のワークスペースが無くても拒否する(自分の既定のナレッジの中だけは可)。これを外すと、ナレッジ画面から `secrets.json` や `timeline.db` を読み書きできてしまうため。
- スペースの作成時にも、既存のワークスペースの保存先が新しいスペースのフォルダを含んでいないかを確かめる(古い設定でアプリデータ全体を保存先にしている場合は、作成を拒否する。保存先を変えてから作る)。
- 保存先の確認から保存までは、他の保存先の変更・削除と交差しないよう、1つのロックの中で行う(`set_location`)。
- 自分自身の保存先とは重なってよい(デバッグログの既定はナレッジの中)。
- 設定のコピーは、ナレッジの保存先(`knowledge_dir`)・デバッグログの保存先(`debug_log_dir`)を対象にしない。ナレッジ本体もコピーしない。

## 決定事項

- スペース名は1〜40文字(制御文字なし)。上限は30件。
  - 「パーソナル」「ワーク」「Personal」「Work」は予約名で、スペース名にできない(大文字小文字・前後の空白は無視。これらを含むだけの名称は可)。
  - 名称もスペース同士で重複禁止。前後の空白を除き、大文字小文字を区別せず比較する(作成・更新とも拒否、削除すると空く)。
- イメージカラーは、あらかじめ用意した30色(`PALETTE`)から選ぶ。自由な色は選べない。
  - スペース同士で色の重複は禁止(作成・更新とも拒否、削除すると空く)。上限と同数なので、必ず空き色がある。
  - パレットは Rust(`services/workspace.rs`)を唯一の定義とし、画面は `list_space_colors` で取得する。
  - 使用中の色は、画面で選べない表示にする。新規作成時は、空いている先頭の色が選ばれている。
- スペースの削除は、アプリが管理するフォルダ(`workspaces/<id>/`)をすべて消す(会話・設定・APIキー・既定の場所のナレッジ)。利用者が独自に指定したナレッジの保存先は消さない。元に戻せないため確認を取る。
  - 裏で動いている整理バッチ・会話は、削除の印を見て、書き込む前に止まる(削除後にフォルダやファイルを作り直さない)。
  - 切り替え・読み込み・作成・更新・削除は1つのロックで直列にし、削除と交差しても、削除済みのスペースを選択・読み込みしない。選択中の ctx が見つからないときは、パニックせずパーソナルへ戻す。
- デバッグログの出力先・有効/無効は、ワークスペースごとの状態(`WorkspaceCtx.debug`)として持つ。選択を切り替えても、裏で動くワークスペースのログは自分のワークスペースにだけ書かれる。
- MFA コードの入力要求には、求めているワークスペース(名称と色)を載せ、コードはそのワークスペースへ返す。選択中とは限らない裏のスペースが求めても、入力欄でどのスペースか分かり、正しい相手へ届く。複数が同時に求めたら、順に出す。AWS の一時認証と MFA 待ちは、同じワークスペースを開き直した ctx の間で共有する(`Shared`)。
- Bedrock のモデル一覧は秘密ではない設定項目なので、キーをコピーしないときも写す(AWS の認証情報は写さない)。
- 依頼の記録(進捗・承認待ち・結果)はメモリ上のみ。アプリを再起動すると、裏で動いていた依頼は終わり、依頼を始める前の状態で起動する(会話の本文はDBに残る)。再起動後に再開はしない。
- スペースの切り替え用のキーボードショートカットは設けない(画面・メニューバー・トレイから切り替える)。
- コード上の識別子も「Space」に統一している(`Space`・`create_space`・`list_spaces` など)。保存データの形式(`workspaces/registry.json` の項目、`workspaces/<UUID>/`)は変えていない。
- 設定のコピーは、検証 → キー → コマンド権限 → 設定(トランザクション)の順に書き、途中で失敗したらキーとコマンド権限を元へ戻す。コピー先が選択中なら、失敗しても表示を更新する。
- 聞き取り訂正のキャッシュ(`SessionContexts`)は、ワークスペースとセッションの組で持つ。訂正の追加はそのワークスペースの分だけ、スペースの削除はその分を捨てる。
- 一覧ファイルが壊れていたら`registry.json.corrupt`へ退避して空から始める。スペースのフォルダは消さない。

## 未対応・要判断

最終判断のために、現時点で未対応のものをまとめています。

| 項目 | 現状 | 影響 |
| --- | --- | --- |
| 設定のコピーの対象外 | 読み上げ辞書、ナレッジ、会話、ナレッジの保存先(`knowledge_dir`)はコピーしない | 辞書はスペースごとに登録し直す。コピー先のナレッジの保存先は既定のまま |
| キーのコピーは上書き方式 | コピー先にだけあるキーは残し、同じキーは上書きする(コピー元にあるキーは、削除の同期はしない) | コピー元でキーを削除しても、コピー先には残る |
| 関連ノートのキャッシュ | `GraphCache` はグローバルで1件分(ルートのパスで識別) | 動作上は混ざらない。切り替えのたびに作り直す |
| 戻ったときの返答は読み上げない | 離れている間に終わった返答は、字幕・履歴に出すだけで、自動では読み上げない | 読み上げたい場合は、メッセージ横のスピーカーボタンから再生する |
| 依頼の再開の実機確認 | 承認ダイアログの復元と音声での返答の待ち受け、画面を離れたあとの挙動は、実機では未確認(Rust側はテスト済み) | 実機で、承認待ちのまま切り替えて戻る操作を確認する必要がある |
| 常時待機 | 切り替えで対話画面を作り直すため止まる。切替先で待機設定がオンなら再開する想定だが、実機では未確認 | 再開しない場合は、対話画面でマイクを入れ直す |
| 終了時のバッチ | 開いているワークスペースだけが対象 | 未起動のスペースの未処理ログは、次回の定期バッチまで残る |
| パーソナルの既存の保存先 | パーソナルがすでに独自のナレッジの保存先(例: Obsidian の vault)を使っている場合、その場所はスペースから選べない | 意図どおり。重ねたい場合は、保存先の重なり禁止を緩める必要がある |
| 実機での確認 | Rustは `cargo test`、フロントは lint・型・静的ビルドまで。画面の実機確認(切り替え、音声、色の表示、レイアウト)は未実施 | 実機で確認が必要 |
