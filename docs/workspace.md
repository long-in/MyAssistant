# ワークスペース

パーソナルと、ワークの複数エージェントを、完全に分けて使う機能です。

- **パーソナル**: 従来のエージェント(パーソナルエージェント)。保存場所は変えていません(アプリデータ直下)。
- **ワーク**: 仕事用。最大30件のワーキングエージェントを作れます。各ワーキングエージェントは独立して動き、名称とイメージカラーを持ちます。会話・整理などの LLM の処理は、常にエージェント専用のコンテナ内の Claude Code で行います([sandbox.md](sandbox.md))。ワークは全体設定で有効にしたときだけ使え、有効にするとリーダーが作られます([leader.md](leader.md))。
- **リーダー**: ワークのエージェントへ指示を配布し、進捗を台帳で管理する別枠のエージェント([leader.md](leader.md))。

## 保存場所

| 対象 | 場所 |
| --- | --- |
| パーソナル | `<アプリデータ>/timeline.db`、`secrets.json`、`knowledge/`(従来どおり) |
| エージェント | `<アプリデータ>/work/<UUID>/` に同じ構成 |
| リーダー | `<アプリデータ>/work/leader/` に同じ構成([leader.md](leader.md)) |
| エージェント一覧 | `<アプリデータ>/work/registry.json`(id・名称・色・作成日時) |
| 全体設定・共通データ | `<アプリデータ>/work/global_settings.db`、`work/shared_data.json`(全ワークスペース共通。[global-settings.md](global-settings.md)) |

分離するもの: 設定・会話・API 方式の権限(`timeline.db`)、APIキー・AWS設定(`secrets.json`)、サンドボックスの環境変数(`sandbox.env`)・Dockerのコンテナとボリューム(Dockerfileとイメージは共通。専用の登録があれば `agent-sandbox/`)([sandbox.md](sandbox.md))、ナレッジ(記憶・スキル・聞き取り訂正を含む)、デバッグログ、読み上げ辞書。

共有するもの(端末の資源): Whisper・VOICEVOX・VAD・ローカル LLM のモデルとエンジン、録音、定型音声(`voice/`)、全体設定、プロキシのパスワード(`proxy/secrets.json`)。

## 構成(`services/workspace.rs`)

- `WorkspaceCtx`: 1ワークスペース分の状態(`db`・`secrets`・`debug`、全体設定 `global`、共有状態 `shared`)。
- `Workspaces`: 読み込み済みの ctx、選択中の ID、エージェント一覧、リーダー(別枠)。エージェントを読み込むのは、切り替えたとき・作ったときだけ。整理バッチ・全エージェントのナレッジ・保存先の確認のためには、一時的に開いて使い終わったら捨てる(`open_for_knowledge` など)。
- `Shared`: 同じワークスペースを別々に開いた ctx の間で共有する状態(整理バッチの多重実行ガード `batch`・削除の印・依頼の実行状態 `task`・AWS の一時認証と MFA 待ち `aws`)。一時的に開いたものと読み込み済みのものが、同じバッチを二重に動かしたり、削除に気づかなかったりしない。
- 開くとき(起動時・切り替え時・作成時)に、ナレッジのフォルダ名を小文字にそろえ、アプリが使うフォルダを作る(`prepare_knowledge`。[knowledge.md](knowledge.md#保存先))。
- コマンドは `ctx: Ctx` で選択中のワークスペースを受け取る。処理の途中で切り替わっても、受け取った ctx を使い続けるため混線しない。

## 画面

- 左端の**エージェントレール**(`AgentRail`、幅固定)に、Personal と各エージェント(色付きの丸+頭文字)を常に並べ、1クリックで切り替える。末尾の「+」は、名称とイメージカラーを入力する作成ダイアログ(`CreateAgentDialog`)を開く。作成すると、そのエージェントへ切り替える。メニューを畳んでもレールは残る。
- その右の機能メニュー(`AppShell`)の上部に、いまの居場所(PERSONAL / WORK とエージェント名・色)を示す。項目は、エージェントごとのもの=主要(Chat / Knowledge / Settings。デバッグモードがオンなら Debug も。ログはワークスペースごと)と、エージェントを切り替えても変わらないもの=補助(All Knowledge / Global Settings / Shortcuts)に分け、選択中の項目はエージェントの色にする。
- macOS のメニューバーとトレイにも「Agents」があり、Personal と各エージェントへ直接切り替えられる。トレイの先頭には、いまのワークスペースを表示する。
- 表記の方針: 左メニューの項目、macOS のメニューバーとトレイ、切り替え(Personal / Work)、バッジは**英語に固定**する。エージェントの作成ダイアログ、設定のコピーの確認、通知のトースト、MFA 入力欄のエージェント表示、エージェントのエラー文言は、**言語設定(日本語 / 英語)に従う**。
- レールは、各エージェントの依頼の状態も示す(`useAgentRuns`。3秒ごと・通知のたびに `leader_overview` を読み直す。直接の指示による依頼も含む)。実行中=周りを回るリングと青い点、承認待ち=脈打つ琥珀色の点、完了=緑の点、失敗=赤の点。待機中(動いていない)のエージェントは淡く表示する。完了・失敗の点は、そのエージェントを開いて結果を受け取ると消える。
- エージェントの色は、メニュー上部のロゴ、画面上端の細い帯、選択中のメニュー項目に出る(CSS 変数 `--workspace-color`)。
- エージェントの作成はレールの「+」、名称と色の変更・設定のコピー・削除は、各エージェントの設定の「その他」タブで行う(専用の管理画面は無い)。
- 切り替えると、対話画面は作り直され(読み上げ・録音・常時待機が止まる)、切替先でAPIキーの有無を確かめる。会話のセッションはワークスペースごとに保持し、戻ると同じ会話の続きになる。

## 依頼の継続と再開

ワークスペースを切り替えても、実行中の作業の依頼(ファイル操作・コマンド)は止めない。承認が要るときは回答を待ち、そのワークスペースへ戻ったら、回答して再開できる。

- 依頼の進捗・承認待ち・結果は、ワークスペースごとに記録する(`services/task_run.rs`の`TaskState`。進捗は新しい側の最大500件、メモリ上のみで、アプリを再起動すると消える。会話の本文はDBに残る)。
- 画面は、離れるとき `task_detach` で接続を外し(依頼は止まらない)、戻ったとき `task_resume` で状況を受け取って接続し直す。
  - 実行中なら、「処理中」の表示・進捗ログ・承認ダイアログを戻す。承認ダイアログが出れば、音声での返答の待ち受けも始まる。回答すれば、そのまま続く。
  - 離れている間に終わっていれば、結果をやり取りに加える。**自動では読み上げない**(戻った直後に話し出さないため)。
  - 戻った画面が受け取った続きの進捗と結果は、イベント(`finished`)で届く。最初の画面は、これまでどおりコマンドの戻り値で結果を受け取る(二重に受け取らない)。
- 承認待ちの時間切れ(120秒)は、そのワークスペースを選んでいる間だけ数える。裏にいる間は止まる。
- 画面を離れたあとに返答が届いても、読み上げたり、やり取りへ加えたりしない(結果は戻ったときに受け取る)。
- エージェントを削除すると、そのエージェントの実行中の依頼を中断する(動いているコマンドは強制終了、承認待ちは拒否)。

## 開いていないエージェントの通知

選択中ではないワークスペースで対応が必要になったら、トーストで知らせる(`services/attention.rs`、画面は `AttentionToasts`)。

- 通知する場面:
  - 承認が必要になったとき(警告のトースト)。承認待ちのまま別のエージェントへ移ったときにも、改めて知らせる。
  - 依頼が完了したとき(成功のトースト)。
  - 依頼が失敗したとき(エラーのトースト。失敗の理由を添える)。
- 表示は言語設定に従う。日本語は「`<エージェント名>`: 承認が必要です / 依頼が完了しました / 依頼が失敗しました」(パーソナルは「パーソナル」)。承認は、求められている内容(コマンド・作成するファイル・計画。バックエンドは種類と値を分けて渡し、画面が言語に合わせて文にする)も添える。
- 「開く」(Open)を押すと、そのエージェントへ切り替えて対話画面を開く。承認は、戻れば答えられる(依頼の継続と再開、前節)。
- 承認の通知は、対応するまで消えない。完了・失敗の通知は30秒で消える。同じエージェント・同じ種類の通知は重ねず、置き換える。そのエージェントを開いたら、そのエージェントの通知は消す。
- アプリが背面にある、またはウィンドウが閉じて(隠れて)いるときは、同じ内容を macOS の通知(`tauri-plugin-notification`)でも出す(決定済み)。全体設定の「OSの通知」でオン/オフでき、既定はオン(全体設定。[global-settings.md](global-settings.md))。オンにするとき、初回は OS の許可ダイアログが出る。通知を押すとアプリが前面に出るが、そのエージェントへは自動で切り替えない(トーストの「開く」で開く)。文言は言語設定に従う。
- 同じエージェントで、対話画面以外(設定・ナレッジなど)を開いている間に承認が必要になったら、トースト(「開く」で対話画面へ)で知らせる(決定済み)。対話画面を開く・承認に答えると消える。アプリが背面なら、OSの通知も出す。承認のダイアログ自体は、従来どおり対話画面にある。
- ナレッジ・デバッグログの保存先は、パーソナル・ほかのエージェントと重ねられない(決定済み)。パーソナルがすでに独自の保存先を使っていれば、その場所はエージェントから選べない。
- 選択中のエージェントの依頼は、通知しない(画面が見ているため)。削除されたエージェントの通知も出さない。
- バックエンドの全体のイベント `task-attention` で届けるので、どのエージェントを開いていても受け取れる。

## 設定のコピー

各エージェントの設定の「その他」タブにある「Copy settings」で、パーソナルまたは別のエージェントの設定を、開いているエージェントへ写す(`copy_workspace_settings`、`settings_transfer::copy`)。コピー元は変更しない。

### 操作

- コピー元を選び、「Copy…」を押す。コピー先は開いているエージェントに固定する(パーソナル・リーダーへはコピーしない)。コピー元は、未選択ならコピー先以外の先頭(パーソナル)になる。
- 入口は、各エージェントの設定の「その他」タブの「設定のコピー」カード**1か所だけ**(パーソナル・リーダーの設定には出ない)。
- 実行の前に、**必ずアプリ内の確認モーダル**(`CopyConfirmModal`)を出す。コピー元→コピー先、コピーするもの、コピーしないもの、「コピー先の同じ設定が上書きされ、元に戻せない」ことを示す。既定のフォーカスは「Cancel」。実行中は閉じられない。コピー元・コピー先のどちらかが削除されていたら、実行させない。

### 内容

- 対象: 設定のエクスポートと同じ項目(モデルの選択・音声・調整値・整理と校正のモデル・プロンプトの上書き・Sandbox の上限時間と settings.json・プロキシの選択など。[data-and-settings.md](data-and-settings.md#設定のエクスポートインポートsettings_transferrs))。API 方式の権限の settings.json も設定項目として含む。
- 既定ではコピーしないもの: APIキー・AWS設定(スイッチ「Also copy API keys」)。キーのコピーは上書き方式(決定済み)。コピー先にだけあるキーは残し、同じキーはコピー元の値で上書きする。コピー元での削除は同期しない。
- 読み上げ辞書は、任意スイッチ(初期状態OFF)でコピーできる。コピー先の辞書は置き換わる。
- 常にコピーしないもの: 全体設定の項目(ベースプロンプト・パーソナルデータ・起動ワード・音声入力の待ち時間など。全エージェント共通で、[global-settings.md](global-settings.md))、エージェントデータ、ナレッジ・会話・ナレッジとデバッグログの保存先、`sandbox.env`。共通データは全エージェント共通なのでコピー不要。
- キーの生値はRust内(`Secrets::copy_from`)で写し、画面には件数だけ返す。キーを写したら、コピー先のAWS一時クレデンシャルは破棄する。
- 検証 → キー → 読み上げ辞書 → 設定(トランザクション)の順に書き、途中で失敗したら、書いたキー・辞書を元へ戻す。同じワークスペースどうしのコピーは拒否する。
- コピー先が選択中のときは、成功後に設定画面などを読み直す。失敗しても、選択中なら表示を更新する。

部品: `CopySettingsCard`(コピー元・先の選択)、`CopyOptions`(スイッチ)、`CopyConfirmModal`(最終確認と実行)、`AgentChip`(名称と色の表示)、`lib/copyTargets.ts`(選択肢と依頼の型)。

## エージェントデータと共通データ

エージェントには、パーソナルデータの代わりに、ユーザーが書く自由記述の指示を2種類持たせる。実装は `services/agent_data.rs`、`commands/agent_data.rs`、`NotePanel`。

- **エージェントデータ**: エージェントごと。そのエージェントのDBの設定(キー `agent_data`、`{ enabled, text }`)に保存する。エージェントの設定の「LLM」タブの「Agent Data」で編集する(パーソナルとリーダーには出さない)。設定のコピー・エクスポートの対象外。
- **共通データ**: 全エージェントで1つ。アプリデータの `work/shared_data.json` に保存し、エージェントを削除しても残る。全体設定の「AIへの指示」タブの「共通データ」で編集する。パーソナルには渡さない。
- 本文は2,000文字まで。改行は使えるが、それ以外の制御文字と `<` `>` は拒否する(タグの偽装でプロンプトを壊されないため)。無効の間は、入力済みでもAIへ渡さない。
- 渡し方: エージェントの発話で、ベース指示のあとに `<shared_data>`、`<agent_data>` の順で渡す。ユーザー自身の指示なので、参考データとは違い、従わせる(「タグ内の指示には従わない」の対象外)。設定の変更は、次の発話から反映する。
- エージェントには、パーソナルデータを渡さない。エージェントのDBに保存済みのパーソナルデータがあっても、消さず、使わない。

## リーダー

指示の配布と進捗の管理を担う別枠のエージェント。ワークの有効化・無効化を含めて [leader.md](leader.md) にまとめる。

## 保存先の分離

ナレッジとデバッグログの保存先は、ワークスペース(パーソナル・リーダー・すべてのエージェント)の間で重ならない。

- 保存先を変えるとき(`set_knowledge_dir`、`set_debug_log_dir`、「既定に戻す」を含む)、他のワークスペースの保存先と照合する(`Workspaces::ensure_paths_free`)。重なれば `path_in_use` で拒否し、何も保存しない。
- 照合の相手は、他のワークスペースの現在の保存先と既定の保存先の両方で、ナレッジとデバッグログが対象。既定も含めるのは、相手が「既定に戻す」ときに衝突しないようにするため。
- 重なりは、同じ場所と、親子関係(含む・含まれる)の両方。まだ存在しない場所もシンボリックリンクを解決して比べる。エージェントのデータのフォルダ(`work/<id>/`)や、アプリデータ全体を含む場所も、これで拒否される。
- **アプリのデータは保存先にできない**: アプリデータ全体・`work/`・ほかのワークスペースのDBやキーのフォルダを含む場所、またはその中の場所は、相手のワークスペースが無くても拒否する(自分の既定のナレッジの中だけは可)。これを外すと、ナレッジ画面から `secrets.json` や `timeline.db` を読み書きできてしまうため。
- エージェントの作成時にも、既存のワークスペースの保存先が新しいエージェントのフォルダを含んでいないかを確かめる(古い設定でアプリデータ全体を保存先にしている場合は、作成を拒否する。保存先を変えてから作る)。
- 保存先の確認から保存までは、他の保存先の変更・削除と交差しないよう、1つのロックの中で行う(`set_location`)。
- 自分自身の保存先とは重なってよい(デバッグログの既定はナレッジの中)。
- 設定のコピーは、ナレッジの保存先(`knowledge_dir`)・デバッグログの保存先(`debug_log_dir`)を対象にしない。ナレッジ本体もコピーしない。

## 決定事項

- エージェント名は1〜40文字(制御文字なし)。上限は30件。
  - 「パーソナル」「ワーク」「Personal」「Work」は予約名で、エージェント名にできない(大文字小文字・前後の空白は無視。これらを含むだけの名称は可)。
  - 名称もエージェント同士で重複禁止。前後の空白を除き、大文字小文字を区別せず比較する(作成・更新とも拒否、削除すると空く)。
- イメージカラーは、あらかじめ用意した30色(`PALETTE`)から選ぶ。自由な色は選べない。
  - エージェント同士で色の重複は禁止(作成・更新とも拒否、削除すると空く)。上限と同数なので、必ず空き色がある。
  - パレットは Rust(`services/workspace.rs`)を唯一の定義とし、画面は `list_agent_colors` で取得する。
  - 使用中の色は、画面で選べない表示にする。新規作成時は、空いている先頭の色が選ばれている。
- エージェントの削除は、アプリが管理するフォルダ(`work/<id>/`)を消す(会話・設定・APIキー)。利用者が独自に指定したナレッジの保存先は消さない。元に戻せない。
  - 入口は、設定の「その他」タブ(選択中のエージェントのみ。パーソナルには出ない)。同じ確認モーダル(`DeleteAgentModal`)を必ず出し、確認なしには削除しない。既定のフォーカスは「キャンセル」。
  - モーダルで、**既定の場所のナレッジを一緒に削除するか**を選べる。既定は**削除しない**。削除しない場合は、`work/<id>/knowledge/`(デバッグログを含む)を、アプリデータ直下の `kept-knowledge/<名称>-<ID先頭8桁>/` へ移してから削除する。移せないとき(移動先が既にある等)は、何も消さずに失敗する。空のフォルダだけのナレッジ(自動で作った `data/`・`inbox/` などの枠だけ)は残さず、そのまま削除する。残した場所は削除後のトーストで知らせる。残したフォルダはアプリからは使わない(ナレッジの保存先に指定し直せる)。
  - 裏で動いている整理バッチ・会話は、削除の印を見て、書き込む前に止まる(削除後にフォルダやファイルを作り直さない)。
  - 切り替え・読み込み・作成・更新・削除は1つのロックで直列にし、削除と交差しても、削除済みのエージェントを選択・読み込みしない。選択中の ctx が見つからないときは、パニックせずパーソナルへ戻す。
- デバッグログの出力先・有効/無効は、ワークスペースごとの状態(`WorkspaceCtx.debug`)として持つ。選択を切り替えても、裏で動くワークスペースのログは自分のワークスペースにだけ書かれる。
- MFA コードの入力要求には、求めているワークスペース(名称と色)を載せ、コードはそのワークスペースへ返す。選択中とは限らない裏のエージェントが求めても、入力欄でどのエージェントか分かり、正しい相手へ届く。複数が同時に求めたら、順に出す。AWS の一時認証と MFA 待ちは、同じワークスペースを開き直した ctx の間で共有する(`Shared`)。
- 依頼の記録(進捗・承認待ち・結果)はメモリ上のみ。アプリを再起動すると、裏で動いていた依頼は終わり、依頼を始める前の状態で起動する(会話の本文はDBに残る)。再起動後に再開はしない。
- 離れている間に終わった返答は、戻っても自動では読み上げない。字幕の返答の下の「読み上げ」ボタンで、いつでも再生できる(ミュート中でも、押したときは再生。読み上げの準備(TTS)がないときは出ない)。
- 関連ノートのキャッシュ(`GraphCache`)は、アプリ全体で1件だけ持つ。ルートのパスで識別するので混ざらず、切り替えて戻ったときは作り直す。
- エージェントの切り替えは、画面・メニューバー・トレイのほか、`Mod`+`K` の検索パレット(`AgentPalette`。パーソナルと全エージェントを名称で絞り込み、Enterでそのエージェントのチャットへ移る)からも行える。
- コード上の識別子も「Agent」に統一している(`Agent`・`create_agent`・`list_agents` など)。旧「Space」の名称のうち、設定キー `space_data` は DB のマイグレーションで `agent_data` へ移している。`registry.json` の項目は変えていない(フォルダは以前の `workspaces/` から `work/` へ改名した。移行処理は無く、旧フォルダは読まない)。ファイル操作・コマンドを行う従来の「agent」は「task」系の名前(`services/tool_loop.rs`・`services/task_run.rs`・`TaskEvent` など)へ改めた。
- 聞き取り訂正のキャッシュ(`SessionContexts`)は、ワークスペースとセッションの組で持つ。訂正の追加はそのワークスペースの分だけ、エージェントの削除はその分を捨てる。
- 一覧ファイルが壊れていたら`registry.json.corrupt`へ退避して空から始める。エージェントのフォルダは消さない。

## 未対応・要判断

最終判断のために、現時点で未対応のものをまとめています。

| 項目 | 現状 | 影響 |
| --- | --- | --- |
| 依頼の再開の実機確認 | 承認ダイアログの復元と音声での返答の待ち受け、画面を離れたあとの挙動は、実機では未確認(Rust側はテスト済み) | 実機で、承認待ちのまま切り替えて戻る操作を確認する必要がある |
| 常時待機 | 切り替えで対話画面を作り直すため止まる。切替先で待機設定がオンなら再開する想定だが、実機では未確認 | 再開しない場合は、対話画面でマイクを入れ直す |
| 実機での確認 | Rustは `cargo test`、フロントは lint・型・静的ビルドまで。画面の実機確認(切り替え、音声、色の表示、レイアウト)は未実施 | 実機で確認が必要 |
