# ハーネス

タスクごとに「どのデータを参照し、どのツールを使い、どう進めるか」を定義しておき、チャットの実行に適用する機能。実装は `services/harness.rs`(保存・検証・選定)、適用は `services/tool_loop.rs`(`Env` の `limits`)と `commands/task.rs`(`run_with_tools`)、コマンドは `commands/harness.rs`、画面は `src/app/harness/page.tsx`。

対象はパーソナルとエージェント。ハーネスは**エージェントごと**に持つ([workspace.md](workspace.md))。リーダーには適用しない(ツールが別体系のため)。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| 保存 | ナレッジ直下の `Harness/<名前>.md`(通常のナレッジ)。ナレッジ画面からも直接編集できる |
| 選び方 | チャットの入力欄で名前を指定する。「自動」なら、発話ごとに軽量モデルが全ハーネスの名前・説明・呼び出し語から最大 1 件を選ぶ(スキルの選定と同じモデル `skills_route`) |
| 働き方 | 権限を**絞る方向にだけ**働く。広げることはできない(コマンド実行・Web 検索は従来どおり設定で有効なときだけ使える) |
| 手順の自由度 | 進め方は本文の指示文で書く。固定のステップ列は持たず、LLM が判断する |
| 実行ログ | 選ばれたハーネス(自動選定の結果を含む)を、実行ログへ「ハーネス 名前」として残す |

## ファイル形式

```markdown
---
description: "週報を作る"
triggers: ["週報", "今週のまとめ"]
paths: ["Projects", "Memory"]
tools: ["list_files", "read_file", "search_files"]
max_steps: 10
output: "箇条書きで、見出しは3つまで"
---

(進め方の本文)
```

| キー | 内容 |
| --- | --- |
| `description` | 説明(必須。100 文字まで) |
| `triggers` | 自動選定のヒントになる呼び出し語(10 個・1 つ 20 文字まで) |
| `paths` | 参照してよいナレッジのフォルダ(ナレッジ直下からの相対。10 件・100 文字まで)。空なら制限しない |
| `tools` | 使えるツール。`list_files` `read_file` `search_files` `remember` `forget` `create_file` `propose_plan` `run_command` `web_search` `web_fetch`。空なら制限しない |
| `max_steps` | LLM を呼ぶ回数の上限(1〜40)。既定(20 回、コマンド実行が有効なら 40 回)を**超えては**上がらない |
| `output` | 出力形式の指示(300 文字まで・1 行) |
| 本文 | 進め方の指示(必須。3,000 文字まで) |

- 値は JSON の文字列・配列で書く(YAML としても読める)。名前はファイル名を正とする。未知のキーは無視する。Frontmatter の無いファイルは、全体を本文として読む(説明が空なので、検証に通らず使われない)。
- 名前は英数字(日本語を含む)・`_`・`-` のみ、40 文字まで。大文字小文字を区別せず重複を拒否する。作成後に名前は変えられない。
- `paths` は `..`・絶対パス・`.` 始まりの要素を拒否する。説明・呼び出し語に `<` `>`・制御文字は使えない。
- 検証に通らないファイル(ナレッジ画面で編集した結果など)は**実行に使わず**、ハーネス画面に理由つきで表示する。シンボリックリンクのファイルは読まない。

## 実行への適用

1. 発話ごとに、`harness::resolve` が使うハーネスを決める(指定があればそれ。無ければ自動選定。指定した名前が無ければエラー)。
2. 本文と `output` を `<harness>` として、基本情報の後(エージェントデータ・覚えておくことと同じ、ユーザーが書いた指示の位置)に添える。承認・制限・安全上の決まりは変わらない旨も添える。
3. `commands/task.rs` が、許可していないツールを**定義・ガイドから外す**。`tools` を指定したときは、スキルの選定・ツールも使わない(トークンも使わない)。
4. `tool_loop::run_call` が、許可していないツールを**呼ばれても拒否する**(定義から外すだけにしない)。
5. `paths` があれば、`list_files` / `read_file` / `search_files` を範囲内に限る。判定は正規化後の実パスで行うので、範囲内のシンボリックリンクを使った迂回はできない。範囲の手前のフォルダの一覧は、範囲へ続く名前だけを返す。場所を指定しない検索は、範囲ごとに検索する。

## 他の処理との関係

- `Harness/` は、整理バッチ(追記先・出力先)・グラフ・直近の文脈の対象にしない(`Memory/` と同じ扱い。`harness::is_harness`)。LLM の `create_file` でも作れない。ハーネスは画面から登録する。
- アプリ全体のバックアップ(zip)にはナレッジごと含まれる([backup.md](backup.md))。設定のエクスポート(JSON)には含めない。
