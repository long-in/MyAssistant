# サンドボックス(エージェントごとのコンテナで Claude Code を動かす)

エージェントごとに専用の Docker コンテナを持ち、**エージェントの作業そのもの(LLM への問い合わせ・調査・コマンド実行・ナレッジの編集)をコンテナの中で行う**機能です。アプリは指示(プロンプト)をコンテナへ渡し、コンテナ内の Claude Code の途中経過と回答を受け取って表示します。指示が続けば、同じ会話(セッション)のまま繰り返します。

> 状態: 初版(会話をコンテナ内の Claude Code で実行する)まで実装済みです。会話以外の機能のコンテナ化など、後回しにした項目は末尾の「後回しにした項目」で管理します。

## 目的

- エージェントがそれぞれ独自の環境(ツール・認証情報・作業フォルダ)を持ち、ルールに沿って動く。
- 認証情報はエージェントごとに分け、ほかのエージェントや端末の認証情報に触れさせない。
- 担当するシステムのソースコードなどをエージェントごとにマウントし、コンテナ内で LLM に調査させる。
- 最終的には、エージェント(ワークスペース)の機能をすべてコンテナの中で動かす。初版は会話(チャット)から始める(「後回しにした項目」)。

## 対象と切り替え

- 設定は**全体設定**(`sandbox_enabled`、既定は無効)。全体設定画面の Sandbox のスイッチで切り替えます。エージェントごとの切り替えはありません。
- 有効なときは、**パーソナルとワークの全エージェント**がコンテナで動きます。ホストでの実行へ切り替える(フォールバック)ことはなく、Docker が使えなければエラーにします。
- リーダーは対象外です(配布と台帳の参照だけで、作業をしないため)。
- パーソナルの音声対話も対象です。Claude Code の起動に毎回数秒かかるため、応答は遅くなります(「後回しにした項目」の常駐化で改善予定)。

## 構成

```text
[アプリ(ホスト)]  チャット画面・会話の記録・設定画面
   │ ① 指示(stdin)+ 認証情報(実行ごとに環境変数)
   ▼ docker exec -i ... claude -p --output-format stream-json --verbose [--resume <セッションID>]
[エージェント専用コンテナ  myassistant-<ランダム8桁>]
   Claude Code ──→ Anthropic API(APIキー) / Amazon Bedrock(AWS 一時キー)
      │ 調査・編集・コマンド(git、AWS CLI など)
   /workspace   = 担当システムのフォルダ(エージェントごとに選ぶ。読み書き)
   /knowledge   = そのエージェントのナレッジ(読み書き)
   /home/agent  = 専用ボリューム(~/.claude の会話・設定、インストールしたツール)
   │ ② 途中経過(テキスト・ツール呼び出し)を逐次 ③ 最終回答・セッションID・使用量
   ▼
[アプリ]  画面へ表示し、会話に記録。続きの指示は ③ のセッションIDで再開する
```

- イメージ: 共通 `myassistant-sandbox:<ハッシュ>`、専用の登録があるエージェントは `myassistant-sandbox-<ID先頭8桁>:<ハッシュ>`。
- ネットワーク `myassistant-net-<UUID>`、ボリューム `myassistant-home-<UUID>`(どちらもエージェントごと)。

## 1回の指示の流れ

実装: `services/sandbox_agent.rs`(`run_turn`)、会話への接続は `commands/chat.rs`(`send_chat_sandbox`)。

1. アプリが、エージェントの認証情報(`sandbox.env` と AWS の一時キー)を用意し、接続先に必要なものがそろっているか確かめる。AWS の一時キーの期限が切れていれば、ここで MFA の入力を求める(「認証情報」)。
2. 必要ならイメージをビルドし、コンテナを作って起動する。
3. `docker exec -i` で Claude Code をヘッドレスモード(`claude -p --output-format stream-json --verbose --permission-mode acceptEdits`)で起動する。
   - 指示は**標準入力**で渡す(長い指示に対応し、プロセスの引数に残さないため)。
   - ルールは `--append-system-prompt` で渡す(「ルールと権限」)。
   - 続きの指示なら、保存しておいたセッション ID を `--resume` で渡す。
   - 作業ディレクトリは `/workspace`(未設定なら `/knowledge`)。
   - **可変の値(システムプロンプト・セッション ID・ツールのリスト)はシェルへ埋め込まず**、`MYASSISTANT_` で始まる環境変数で渡してコマンドから参照する。この名前は `sandbox.env` では使えない。
4. `stream-json` の出力を1行ずつ読み、画面へ逐次流す。
   - `system`(初期化): セッション ID を得る。
   - `assistant`: テキストとツール呼び出しを、今のチャット画面の表示(ツールの進捗)へ対応づける。
   - `user`(ツールの結果): 結果の要約を進捗として表示する。
   - `result`: 最終回答・使用量・費用・エラーかどうか。
   - イメージのビルドの進捗は、「サンドボックスの準備」として表示する。
5. 最終回答を会話に記録し、キャプチャへ書き出す。セッション ID はアプリの会話 ID と対にして保存する(`sandbox_claude_sessions`、直近 50 件)。新しい会話を始めたら、新しいセッションになる。
6. 出力に認証情報の値が出たら、伏せ字にしてから画面と記録へ渡す。

- 中断・時間切れでは、コンテナ内のプロセスグループごと止める。それまでの作業はセッションに残るので、セッション ID は保存し、続きの指示で引き継ぐ。
- 中断したら「作業を中断しました。」を回答として記録する。時間切れ・Claude Code のエラー(認証の失敗など)はエラーとして画面に出す。
- 1回の指示の上限時間は、エージェントの設定で 1〜180 分(既定 30 分)。
- 費用・使用量(`result` の `total_cost_usd` と `usage`)は、アプリのログに残すだけ(「後回しにした項目」)。
- `~/.claude` は専用ボリュームにあるため、コンテナを作り直しても会話のセッションは残る。
- サンドボックスでは、このアプリのモデルの選択(ルート)と API キーは使わない。モデルが登録されていなくても送信できる。

## 認証情報

すべて**実行ごとに環境変数で渡し**、ファイルとしてはコンテナに置きません。

- **Anthropic API**: `sandbox.env` に `ANTHROPIC_API_KEY` を書く。アプリに登録した API キー(`secrets.json`)は渡さない(`secrets.rs` の外へ出さない方針を保つ)。
- **Amazon Bedrock**: アプリに登録したそのエージェントの AWS 設定から、**ホスト側で STS の一時キーを発行して渡す**(ロールの引き受けと MFA の入力はホストで行う)。Claude Code 向けに `CLAUDE_CODE_USE_BEDROCK=1` を渡す。リージョンは AWS 設定のプロファイル(`AWS_REGION`)から取る。
- **AWS のリソース**: Bedrock と同じ一時キーで、コンテナ内の AWS CLI などからも使える。接続先が Anthropic API でも、AWS 設定が登録されていれば渡す。
- **接続先とモデル**: エージェントの設定で、接続先(Anthropic API / Bedrock)とモデルを選ぶ。秘密でない値(`CLAUDE_CODE_USE_BEDROCK` `ANTHROPIC_MODEL` など)はアプリが決めて渡す。`sandbox.env` に同じ名前があれば、そちらが優先される。
- 必要な認証情報が無いとき(Anthropic API で `ANTHROPIC_API_KEY` が無い、Bedrock で AWS のキーかリージョンが無い、MFA を入力しなかった)は、実行せずにエラーにする。
- MFA: 一時キーはメモリにキャッシュし、期限内は MFA を聞かない。指示ごとに実行し直すため、毎回期限内のキーが渡る。1回の指示が一時キーの期限を超えると、その途中で AWS の呼び出しが失敗する。AWS 設定の `duration_seconds` を長くして避ける(ロールの最大セッション時間まで。最大 12 時間)。

### 環境変数(`sandbox.env`)

- 置き場所: `<アプリデータ>/workspaces/<UUID>/sandbox.env`(パーソナルはアプリデータ直下)。dotenv 形式、権限 0600。コンテナにはマウントしない。
- 書式: `NAME=value`(1行に1つ)。`#` のコメント、`export ` の接頭辞、`"..."` / `'...'` の囲みに対応。複数行の値は不可。
- **実行のたびに読み直す**ので、保存すれば次の指示から反映される。
- 検証: 名前は英数字と `_`(数字から始まらない)。`PATH` `HOME` `USER` `TERM` など実行の仕組みが使う名前と、`DOCKER_` `LD_` `DYLD_` `MYASSISTANT_` で始まる名前は不可。最大 100 個、値は 8KB まで、制御文字は不可。不正な行は「N行目」を示してエラーにする(値はエラーに含めない)。
- 画面には名前と検証結果だけを返し、値は返さない。
- 値の渡し方: `docker exec -e NAME` の形で**名前だけを引数に書き**、値は docker CLI の環境変数として渡す。`docker inspect` に値は残らない。
- 出力の伏せ字: 8 文字以上の値が出力に出たら `***` に置き換える(`*REGION` で終わる名前、`CLAUDE_CODE_USE_BEDROCK` `ANTHROPIC_MODEL`、`MYASSISTANT_` で始まる名前は対象外)。変形して出力された値(Base64 など)は検知できない。
- `command_policy` の保護対象に `sandbox.env` を含め、ホストのコマンドからも触れない。

## マウント

| コンテナ内 | ホスト | 権限 | マウント |
| --- | --- | --- | --- |
| `/workspace` | エージェントごとに選んだフォルダ(担当システムのソースコードなど) | 読み書き | 設定したときだけ |
| `/knowledge` | そのエージェントのナレッジ | 読み書き | 常に |
| `/home/agent` | 専用ボリューム `myassistant-home-<UUID>` | 読み書き | 常に |

- `/workspace` のフォルダは、エージェントの設定画面で Finder のダイアログから選ぶ(エージェントごとの設定 `sandbox_workspace_dir`。端末ごとに異なるため、設定の書き出し・コピーの対象外)。未設定ならマウントしない。
- 選べないフォルダ: `/`、ホームフォルダそのもの、アプリデータとその配下(`secrets.json`・`timeline.db`・ほかのエージェントのフォルダがあるため)、`~/.ssh`、`~/.aws`、すべてのワークスペースのナレッジ・デバッグログ(現在と既定の場所)と重なる場所、パスに「,」を含む場所。シンボリックリンクは解決してから判定する。保存した後に使えなくなった(消えた・禁止の場所になった)ときは、マウントせずに進めることはせず、エラーにする。
- **読み書きでマウントするため、コンテナ内の作業でホスト側のファイルが変更・削除されうる**。設定画面に注意書きを出す。Git で管理されたフォルダを選ぶことを勧める。
- フォルダの場所を変えると、次の指示でコンテナを作り直す(専用ボリュームは残る)。マウント元はコンテナのラベル `myassistant.mounts` に残して比べる。
- ナレッジは、コンテナ内の Claude Code とホスト側の機能(ナレッジ整理など)の両方から書き換わる。同時に書き換えたときの扱いは「後回しにした項目」。

## ルールと権限

- **ルール**: 通常の会話と同じ、ベースプロンプト(チャット用)・エージェントデータと共通データ(パーソナルは基本情報)・記憶(覚えておくこと)・聞き取りの訂正に、作業環境の説明(`/workspace` と `/knowledge` の役割、認証情報の扱い)を加えて、`--append-system-prompt` で毎回渡す(上限 100KB)。関連ナレッジとスキルの候補は渡さない(Claude Code が `/knowledge` を直接読む)。
- **承認**: 初版では、実行中に画面で承認を求めない。コンテナを境界とし、次のリストの範囲で自動で進める。
  - 権限モードは `acceptEdits`(ファイルの編集は自動)。
  - 許可リスト(`--allowedTools`): エージェントの設定で変えられる。既定は Bash・Read・Edit・Write・Glob・Grep・NotebookEdit・WebFetch・WebSearch・Task・TodoWrite・Skill。
  - 拒否リスト(`--disallowedTools`): エージェントのコマンド権限(`command-policy.json`)の拒否(`deny`)と、どこにあっても拒否する語(`deny_words`)を、`Bash(<コマンド>:*)` の形へ変換して渡す。「,」や括弧を含む項目は渡さない。拒否が許可より優先される。
  - コマンド実行を無効にしているエージェントでは `Bash` を、Web 検索を無効にしているエージェントでは `WebFetch` と `WebSearch` を拒否する。
  - コマンド権限の確認(`ask`)と許可(`allow`)は、初版では使わない(承認を挟まないため)。
  - 許可されないツールは実行されず、その旨がツールの結果として Claude Code に返る。
- 画面での承認(実行中に確認を挟む)は「後回しにした項目」。

## 既存機能との関係

- サンドボックスが有効なとき、エージェントの会話は Claude Code に一本化する。ホスト側のツールループ(ファイル操作ツール・`run_command`・スキルのツール・Web 検索のサーバーツール)は使わない。
- 会話の記録・画面表示・音声の読み上げは、これまでどおりアプリ側で行う(回答のテキストを受け取って使う)。
- ナレッジ整理・校正・要約・メモリなど、会話以外の LLM を使う機能は、初版ではホスト側のまま動く(コンテナへの移行は「後回しにした項目」)。
- コンテナでの実行(`sandbox::exec`。イメージ・コンテナ・環境変数・伏せ字・中断)は、Claude Code の実行と、ホスト側のツールループの `run_command` のコンテナ実行で共有する。会話がコンテナへ移ったため、`run_command` のコンテナ実行は会話からは使われない。

## Dockerfile(共通と、エージェント専用)

- 共通: `<アプリデータ>/sandbox/Dockerfile`(1つ)。初めて使うとき、同梱の標準(`src-tauri/resources/sandbox/Dockerfile`)をコピーする。全体設定画面の Sandbox Image で編集する。
- 専用: `<ワークスペース>/agent-sandbox/Dockerfile`(ワーク: `workspaces/<UUID>/agent-sandbox/`、パーソナル: `<アプリデータ>/agent-sandbox/`)。**登録があれば共通より優先**する。エージェントの設定画面(権限タブの Sandbox)で、共通の内容をコピーして登録し、編集する。「登録を解除」で共通へ戻る。登録後に共通を変更しても、専用には反映されない。
- 編集の方法は2つで、どちらも同じファイルを触る。
  - 画面内: テキストエリアで編集して「保存」(空・256KB 超・NUL 文字を含む内容は保存できない)。
  - 外部のエディタ: 「ファイルを表示」で Finder に出して編集。画面へ戻ると(編集中でなければ)自動で読み込み直す。
- イメージ名は Dockerfile の内容のハッシュで決まる。変更すると、次の指示(または「イメージをビルド」)で1回だけ再ビルドし、そのイメージを使うエージェントのコンテナを作り直す(専用ボリュームは残る)。古いタグは使われなくなってから消す。
- ビルドの文脈は Dockerfile のフォルダだけ。環境変数・認証情報はビルドに渡さない。ビルドは全体で1本ずつ。進捗は `sandbox-build-progress` イベント(`scope` は `shared` かエージェント ID)。
- 標準の内容: `node:22-bookworm-slim`(Claude Code は Node.js 22 以上が必要)に、AWS CLI v2・git・jq・ripgrep・python3 と、Claude Code(`@anthropic-ai/claude-code`、版を固定。現在 2.1.311)を入れたもの。Claude Code の版は Dockerfile の `CLAUDE_CODE_VERSION` を書き換えて更新する。読み取り専用のファイルシステムで動くため、自動更新は止める(`DISABLE_AUTOUPDATER=1`)。
- 崩してはいけない前提: 非 root のユーザー `agent`、`/workspace` `/knowledge` `/home/agent`、`sh` と `setsid`(util-linux)、`claude` コマンド。コンテナを作った直後に、`setsid`・`agent`・`claude` を診断し、満たさなければエラーにする。

## 名前とエージェントの対応

- コンテナ名は `myassistant-<ランダム8桁>`。名前にエージェントの名前や ID を含めない。
- 持ち主はラベル `myassistant.agent=<エージェントID>` で持つ(専用イメージ・ネットワークにも付ける。共通イメージは `myassistant.shared-image=1`)。
- 設定画面の「コンテナ名」で確認できる。`docker ps --filter label=myassistant.agent=<ID>` でも引ける。
- ネットワークとボリュームは ID から決まる名前(`myassistant-net-<ID>`、`myassistant-home-<ID>`)。

## 分離の内容

- マウントは上の表のものだけ。アプリデータ・`~/.aws`・ほかのエージェントのフォルダはコンテナから見えない。
- `--read-only`(`/tmp`・`/var/tmp` は tmpfs)、`--cap-drop ALL`、`no-new-privileges`、`--init`、非 root(`agent`)、メモリ 2GB・CPU 2・プロセス 512 の上限。
- エージェントごとにネットワークを分け、コンテナ同士は通信できない。外向きの通信は制限しない。

## コンテナの寿命と後始末

- コンテナは最初の実行で作り、使い終えても置いておく。最後の実行から約10分で停止し、アプリの終了時と起動時にすべて止める。
- エージェントを削除すると、コンテナ・ネットワーク・ボリューム・専用イメージを消す(共通イメージは残す)。
- バックアップには `sandbox.env`(平文)、共通の Dockerfile(`sandbox/`)、専用の Dockerfile(`agent-sandbox/`)を含める。専用ボリューム(`~/.claude` のセッションを含む)は含めない。

## 設定画面

- 全体設定画面の Sandbox: スイッチ。
- 全体設定画面の Sandbox Image: 共通の Dockerfile の編集・ビルド・状態。
- 各エージェントの「権限」タブの Sandbox(リーダーでは出ない):
  - 有効/無効の表示、Docker・コンテナの状態、コンテナ名、コンテナを作り直す。
  - `/workspace` にマウントするフォルダの選択・解除と注意書き。
  - Claude Code の接続先(Anthropic API / Bedrock)・モデル・1回の指示の上限時間・許可するツール(`sandbox_llm`。設定の書き出し・コピーの対象)。
  - 専用の Dockerfile の登録・編集。
  - `sandbox.env` の名前一覧と検証結果。
- 実行ログと進行中の表示は、Claude Code のツール(`Bash`・`Read`・`Edit` など)を分かる名前で表示する。

## 決定事項

- docker CLI だけに対応する(Docker Desktop / OrbStack など)。探す場所は `/usr/local/bin` `/opt/homebrew/bin` `/Applications/Docker.app/Contents/Resources/bin` `~/.orbstack/bin` と `PATH`。
- コンテナ内は Linux。`brew` `open` `osascript` などホストの macOS 固有のコマンドは使えない。
- 外向きのネットワークは制限しない。
- Claude Code の API キーは `sandbox.env` で渡す。アプリに登録した API キーは渡さない。
- 初版では実行中の承認を挟まない(許可・拒否のリストで制御する)。

## 既知の限界

- 同じ Docker ホスト上の root 権限を持つ者や、Docker の脆弱性までは防がない(コンテナによる分離の範囲)。
- コンテナ内の Claude Code とコマンドは、渡された認証情報の値を読める。外向きの通信を制限しないため、値を外へ送ることも技術的には可能。渡すのは、そのエージェントが使う分だけにする。
- 実行中、`sandbox.env` の値は docker CLI のプロセスの環境変数にある。同じユーザーの別プロセスから短時間見える可能性がある。
- `/workspace` と `/knowledge` は読み書きでマウントするため、コンテナ内の作業でホスト側のファイルが変更・削除されうる。
- 1回の指示が AWS の一時キーの期限を超えると、途中で AWS の呼び出しが失敗する。
- 端末内の LLM(`local_llm`)は、Docker for Mac のコンテナでは GPU(Metal)を使えないため、コンテナ内では実用的な速度にならない。
- 同梱テンプレートの更新は、各 Dockerfile へ自動反映されない。
- 拒否ルールは Claude Code のコマンドの接頭辞の判定に従う。`deny_words`(どこにあっても拒否する語)も接頭辞のルールとして渡すため、ホスト側の判定ほど厳密ではない。
