# サンドボックス(エージェントごとのコンテナで Claude Code を動かす)

エージェントごとに専用の Docker コンテナを持ち、**エージェントの作業そのもの(LLM への問い合わせ・調査・コマンド実行・ナレッジの編集)をコンテナの中で行う**機能です。アプリは指示(プロンプト)をコンテナへ渡し、コンテナ内の Claude Code の途中経過と回答を受け取って表示します。指示が続けば、同じ会話(セッション)のまま繰り返します。

> 状態: 初版(会話をコンテナ内の Claude Code で実行する)まで実装済みです。会話以外の機能のコンテナ化など、後回しにした項目は末尾の「後回しにした項目」で管理します。

## 目的

- エージェントがそれぞれ独自の環境(ツール・認証情報・作業フォルダ)を持ち、ルールに沿って動く。
- 認証情報はエージェントごとに分け、ほかのエージェントや端末の認証情報に触れさせない。
- 担当するシステムのソースコードなどをエージェントごとにマウントし、コンテナ内で LLM に調査させる。
- 最終的には、エージェント(ワークスペース)の機能をすべてコンテナの中で動かす。初版は会話(チャット)から始める(「後回しにした項目」)。

## 対象と切り替え

- **ワークのエージェントは、常にコンテナで動きます**(切り替えはありません。旧全体設定の `sandbox_enabled` と Sandbox のスイッチは廃止し、保存済みの値は無視します)。ホストでの実行へ切り替える(フォールバック)ことはなく、Docker が使えなければエラーにします。
- **パーソナルとリーダーは、AI Link の接続方式に Bedrock を選んだときだけ**コンテナで動きます。このとき、すべての LLM の機能(チャット・校正・整理・スキルの選定・スキル名の英訳・宛先の提案)をコンテナ内の Claude Code で行い、Anthropic の API のモデルも端末内の Qwen も選べません(保存済みの選択は、コンテナの経路に読み替える。校正だけはオフにする)。API 方式のときは、従来どおりホストでこのアプリの LLM(Anthropic・端末内の Qwen)を使います。Sandbox タブは、パーソナル・リーダーにも出ます。
  - Amazon Bedrock は、このアプリから直接は呼びません(モデル一覧も持ちません)。Bedrock を使うときは、この経路を選び、モデルは settings.json の `model` / `availableModels` で決めます。
  - チャットのモデルの選択肢には、settings.json で許可したモデルごとに「コンテナ内の Claude Code」が並びます。校正・ナレッジ整理(`proofread_route` / `batch_route`)にも選べます。スキルの選定・宛先の提案には選べません(毎回呼ぶため)。
  - 以前の Bedrock のモデルや端末内のモデルを保存していた個人・リーダーのチャット・整理・スキルの選定は、コンテナ内の Claude Code に読み替えます(校正はオフになります)。
  - **リーダー**は、コンテナ内の Claude Code を**ツールなし**で使います。エージェントの一覧と台帳(`agent_list` / `ledger_list` と同じ内容)は毎回の文脈として渡し、配布の下書きは、返答の中の ```` ```dispatch-draft ```` ブロック(JSON)で受け取ります。アプリがブロックを検証して下書きの確認を出し、配布は利用者が確かめてから行います(形式が違うブロックは下書きにせず、本文に残します)。
- ワークのエージェントの音声対話も対象です。Claude Code の起動に毎回数秒かかるため、応答は遅くなります(「後回しにした項目」の常駐化で改善予定)。
- Claude Code の接続先・モデル・上限時間・許可ツールは、エージェントの設定の **LLM タブ**で設定します(`ClaudeCodeSettings`)。Sandbox タブには、状態・`/knowledge/data`・Dockerfile・`sandbox.env` が残ります。パーソナルで接続方式が API のときは、Sandbox タブは「Bedrock 方式のときだけ使えます」という案内だけを出します(接続方式の読み込み前は何も出しません)。

## 構成

```text
[アプリ(ホスト)]  チャット画面・会話の記録・設定画面
   │ ① 指示(stdin。stream-json の user メッセージ)+ 認証情報(実行ごとに環境変数)
   ▼ docker exec -i ... claude -p --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio [--resume <セッションID>]
[エージェント専用コンテナ  myassistant-<ランダム8桁>]
   Claude Code ──→ Amazon Bedrock(AWS 一時キー)
      │ 調査・編集・コマンド(git、AWS CLI など)
   /knowledge      = そのエージェントのナレッジ(読み書き)
   /knowledge/data = 担当システムのフォルダ(ナレッジ直下の data/。ソースコードなど)
   /home/agent  = 専用ボリューム(~/.claude の会話・設定、インストールしたツール)
   │ ② 途中経過(テキスト・ツール呼び出し)を逐次 ③ 最終回答・セッションID・使用量
   ▼
[アプリ]  画面へ表示し、会話に記録。続きの指示は ③ のセッションIDで再開する
```

- イメージ: 共通 `myassistant-sandbox:<ハッシュ>`、専用の登録があるエージェントは `myassistant-sandbox-<ID先頭8桁>:<ハッシュ>`。
- ネットワーク `myassistant-net-<UUID>`、ボリューム `myassistant-home-<UUID>`(どちらもエージェントごと)。

## 1回の指示の流れ

実装: `services/sandbox_agent.rs`(`run_turn`)、会話への接続は `commands/chat.rs`(`send_chat_sandbox`)。

1. アプリが、エージェントの認証情報(`sandbox.env` と AWS の一時キー)を用意し、接続先に必要なものがそろっているか確かめる。AWS の一時キーの期限が切れていれば、ここで MFA の入力や SSO の承認を求める(「認証情報」)。
2. 必要ならイメージをビルドし、コンテナを作って起動する。
3. `docker exec -i` で Claude Code をヘッドレスモード(`claude -p --output-format stream-json --verbose --permission-mode acceptEdits`)で起動する。
   - 指示は**標準入力**で渡す(長い指示に対応し、プロセスの引数に残さないため)。
   - ルールは `--append-system-prompt` で渡す(「ルールと権限」)。
   - 続きの指示なら、保存しておいたセッション ID を `--resume` で渡す。
   - 作業ディレクトリは `/knowledge/data`。
   - **可変の値(システムプロンプト・セッション ID・ツールのリスト)はシェルへ埋め込まず**、`MYASSISTANT_` で始まる環境変数で渡してコマンドから参照する。この名前は `sandbox.env` では使えない。
4. `stream-json` の出力を1行ずつ読み、画面へ逐次流す。
   - `system`(初期化): セッション ID を得る。
   - `assistant`: テキストとツール呼び出しを、今のチャット画面の表示(ツールの進捗)へ対応づける。
   - `user`(ツールの結果): 結果の要約を進捗として表示する。
   - `result`: 最終回答・使用量・費用・エラーかどうか。
   - イメージのビルドの進捗は、「サンドボックスの準備」として表示する。
5. 最終回答を会話に記録し、キャプチャへ書き出す。セッション ID はアプリの会話 ID と対にして保存する(`sandbox_claude_sessions`、直近 50 件)。新しい会話を始めたら、新しいセッションになる。
6. 出力に認証情報の値が出たら、伏せ字にしてから画面と記録へ渡す。

- 中断・時間切れでは、コンテナ内のプロセスグループごと止める。それまでの作業はセッションに残るので、セッション ID は保存し、続きの指示で引き継ぐ。
- 中断したら「作業を中断しました。」を回答として記録する。時間切れ・Claude Code のエラー(認証の失敗など)はエラーとして画面に出す。
- 1回の指示の上限時間は、エージェントの設定で 1〜180 分(既定 30 分)。
- 費用・使用量(`result` の `total_cost_usd` と `usage`)は、アプリのログに残すだけ(「後回しにした項目」)。
- `~/.claude` は専用ボリュームにあるため、コンテナを作り直しても会話のセッションは残る。
- ワークのエージェントの会話では、このアプリのモデルの選択(ルート)は使わない(モデルは Claude Code の設定)。モデルが登録されていなくても送信できる。

## 認証情報

すべて**実行ごとに環境変数で渡し**、ファイルとしてはコンテナに置きません。

- **Amazon Bedrock(固定)**: 接続先は Bedrock だけ(以前の Anthropic API は廃止。保存済みの旧設定は読み込み時に Bedrock へ直す)。アプリに登録したそのエージェントの AWS 設定から、**ホスト側で STS の一時キーを発行して渡す**(ロールの引き受け、MFA の入力、SSO の承認はホストで行う)。Claude Code 向けに `CLAUDE_CODE_USE_BEDROCK=1` を渡す。リージョンは AWS 設定のプロファイル(`AWS_REGION`)から取る。
- **AWS のリソース**: Bedrock と同じ一時キーで、コンテナ内の AWS CLI などからも使える。AWS 設定が登録されていれば渡す。
- **Claude Code の settings.json**: 利用者が貼り付けた内容(JSON のオブジェクト、64KB まで)を、アプリの設定 `sandbox_claude_settings` に保存する。実行ごとに環境変数 `MYASSISTANT_SETTINGS` で渡し、`claude --settings` へ与える(ファイルとしてコンテナには置かない。`~/.claude/settings.json` には書かない)。保存時に検証し、誤りは行・列と理由だけを返す(内容は含めない)。モデル(`model`)、許可するツール(`permissions.allow`)、拒否するツール・コマンド(`permissions.deny`)はここで決める。アプリが決める `--disallowedTools`(コマンド実行・Web 検索を無効にしたときの拒否など)と `--permission-mode` は引数で渡すため、settings.json では緩められない。エージェントの保存が空のときは、全体設定の settings.json(`sandbox_claude_settings_shared`。全体設定画面の Sandbox タブで編集)を使う(全体設定を利用)。全体設定を変えると、次の指示から自動で反映される。エージェントが自分の内容を保存すると個別設定になり、全体設定の変更では更新されない(「全体設定に戻す」で個別の内容を破棄して追従へ戻せる)。どちらも空のときは、既定の拒否(後述)だけを持つ settings(`{"permissions":{"deny":[...]}}`)を渡す。許可は空なので Bash などは使えず、画面に雛形(既定の12ツールの許可と既定の拒否。`get_claude_settings_template`)を入れるボタンを出す(全体設定の画面にも、空のときに出す)。画面は既定で閲覧だけにし、「編集」で書き換えられるようにする(ボタンは「編集」「保存」「全体設定に戻す」)。`env` の値は画面では伏せず、コンテナの出力に出たときは伏せ字にする(`sandbox.env` と同じ)。設定の書き出し・バックアップにはそのまま含まれる。
- **接続先とモデル**: 接続先は Bedrock 固定。モデルは settings.json の `model` で決める。秘密でない値(`CLAUDE_CODE_USE_BEDROCK`)はアプリが決めて渡す。`sandbox.env` に同じ名前があれば、そちらが優先される。
- 必要な認証情報が無いとき(AWS のキーかリージョンが無い、MFA を入力しなかった、SSO を承認しなかった)は、実行せずにエラーにする。
- MFA: 一時キーはメモリにキャッシュし、期限内は MFA を聞かない。指示ごとに実行し直すため、毎回期限内のキーが渡る。1回の指示が一時キーの期限を超えると、その途中で AWS の呼び出しが失敗する。AWS 設定の `duration_seconds` を長くして避ける(ロールの最大セッション時間まで。最大 12 時間)。

### 環境変数(`sandbox.env`)

- 置き場所: `<アプリデータ>/work/<UUID>/sandbox.env`(パーソナルはアプリデータ直下)。dotenv 形式、権限 0600。コンテナにはマウントしない。
- 既定の内容: 初めて画面を開いたとき(またはファイルが無いとき)、説明のコメントだけを入れたファイルを作る(渡す変数は無い)。すでにあるファイルは書き換えない。
- **値が空の行はコンテナへ渡さない**(空のキーで上書きしないため)。
- 書式: `NAME=value`(1行に1つ)。`#` のコメント、`export ` の接頭辞、`"..."` / `'...'` の囲みに対応。複数行の値は不可。
- **実行のたびに読み直す**ので、保存すれば次の指示から反映される。
- 検証: 名前は英数字と `_`(数字から始まらない)。`PATH` `HOME` `USER` `TERM` など実行の仕組みが使う名前と、`DOCKER_` `LD_` `DYLD_` `MYASSISTANT_` で始まる名前は不可。最大 100 個、値は 8KB まで、制御文字は不可。不正な行は「N行目」を示してエラーにする(値はエラーに含めない)。
- **画面で編集する**: エージェントの設定画面(Sandbox タブ)のエディタに、値を含めてそのまま表示する。保存の前に書式を検証し、誤りがあれば「N行目」を示して保存しない。一時ファイルに書いてから置き換え、権限は 0600 のまま保つ。外部のエディタで保存した変更は、画面へ戻ったときに(編集中でなければ)読み込み直す。
- 値の渡し方: `docker exec -e NAME` の形で**名前だけを引数に書き**、値は docker CLI の環境変数として渡す。`docker inspect` に値は残らない。
- 出力の伏せ字: 8 文字以上の値が出力に出たら `***` に置き換える(`*REGION` で終わる名前、`CLAUDE_CODE_USE_BEDROCK` `ANTHROPIC_MODEL`、`MYASSISTANT_` で始まる名前は対象外)。変形して出力された値(Base64 など)は検知できない。
- `command_policy` の保護対象に `sandbox.env` を含め、ホストのコマンドからも触れない。

## マウント

| コンテナ内 | ホスト | 権限 | マウント |
| --- | --- | --- | --- |
| `/knowledge` | そのエージェントのナレッジ(担当システムのフォルダ `data/` を含む) | 読み書き | 常に |
| `/home/agent` | 専用ボリューム `myassistant-home-<UUID>` | 読み書き | 常に |

- マウントするのはナレッジだけ。ワークスペースのフォルダ全体(`secrets.json`・`timeline.db`・`sandbox.env` がある階層)はマウントしないため、キーや DB はコンテナから見えない。
- **担当システムのフォルダ**は、ナレッジ直下の `data/`(コンテナでは `/knowledge/data`)に決まっていて、選べない。ナレッジの保存先を変えれば、新しい保存先の `data/` を使う(旧保存先の中身は移さない)。無ければ、すべてのワークスペース(パーソナル・リーダー・エージェント)で、開いたとき(起動時・切り替え時・エージェント作成時)に作る(`WorkspaceCtx::prepare_knowledge` が他のアプリ用フォルダと一緒に作る)ほか、コンテナの起動時と Sandbox タブを開いたときにも作る。
- ソースコードなどは、このフォルダへ置くか、コンテナ内で `git clone` する。エージェントの設定画面(Sandbox タブ)に場所を表示し、「Finder で開く」で開ける(`get_sandbox_data_dir` / `open_sandbox_data_dir`)。
- **読み書きでマウントするため、コンテナ内の作業でファイルが変更・削除されうる**。設定画面に注意書きを出す。
- `data/` はノートではないので、整理や索引が使うノート一覧・グラフ索引と更新の検出・整理の書き込み先・初期化・書き出し・LLM の `create_file` の対象にしない。ナレッジ画面には表示して中身も開けるが、画面からの作成・編集・移動・削除は拒否する(`knowledge::is_data`。ナレッジ直下の `data`(大文字小文字を区別しない)だけが対象)。
- **エージェントを削除するときは、ナレッジと同じ扱い**(「ナレッジも一緒に削除する」で削除、そうでなければ `kept-knowledge/` へ移して残す。独自の保存先なら消さない)。削除の確認画面に明記する。
- **バックアップには含めない**(ソースコードは Git などで管理され、大きくなりやすいため)。リストアするとナレッジは退避されるので、それまでの `data/` は `restore-backup-<日時>/` の中に残り、新しい `data/` は空から始まる。
- 以前は `/workspace` を別にマウントしていたが、廃止した。以前のフォルダ(`<ワークスペースのフォルダ>/workspace/`)は移さないので、必要なら `data/` へ手動で移す。Dockerfile のテンプレートの `/workspace` は、既存の Dockerfile との互換のため残している(使わない)。
- マウント元(ナレッジの場所)が変わると、次の指示でコンテナを作り直す(専用ボリュームは残る)。マウント元はコンテナのラベル `myassistant.mounts` に残して比べる。
- ナレッジは、コンテナ内の Claude Code(会話・ナレッジ整理)と、ホスト側の機能(画面からの編集など)の両方から書き換わる。同時に書き換えたときの扱いは「後回しにした項目」。

## ルールと権限

- **ルール**: 通常の会話と同じ、ベースプロンプト(チャット用)・エージェントデータと共通データ(パーソナルは基本情報)・記憶(覚えておくこと)・聞き取りの訂正に、作業環境の説明(`/knowledge` と `/knowledge/data` の役割、認証情報の扱い)を加えて、`--append-system-prompt` で毎回渡す(上限 100KB)。関連ナレッジとスキルの候補は渡さない(Claude Code が `/knowledge` を直接読む)。
- **承認**: 初版では、実行中に画面で承認を求めない。コンテナを境界とし、次のリストの範囲で自動で進める。
  - 権限モードは `acceptEdits`(ファイルの編集は自動)。
  - 許可リスト(settings.json の `permissions.allow`): エージェントごとに settings.json で決める(`--allowedTools` は渡さない)。画面の雛形は Bash・Read・Edit・Write・Glob・Grep・NotebookEdit・WebFetch・WebSearch・Task・TodoWrite・Skill。
  - 確認リスト(settings.json の `permissions.ask`): 当たったツールは、実行前に画面で承認を求める。Claude Code が標準出力へ `control_request`(`can_use_tool`)を出し、アプリが `control_response`(allow はツールの入力をそのまま返す / deny は理由を添える)を標準入力へ返す。このため標準入力は結果が届くまで開いておく(`shell::run_prepared_streaming`)。承認の画面と応答(`task_approve`)・待ち時間(120秒。そのエージェントを開いている間だけ数える。超えたら拒否)は他の承認と同じで、種類は `tool_use`。ボタンでだけ承認できる(音声の「はい」では通らない)。中断・実行の時間切れでも拒否になる。「常に許可」(`permissions.allow` への書き戻し)は未対応。ツールを使わない単発の呼び出し(ナレッジ整理・校正)は、すべて拒否するので確認は来ない。
  - 拒否リスト(settings.json の `permissions.deny`): コマンドの拒否は settings.json だけで決める。既定の拒否は、コマンド権限の初期値の拒否(`deny`)と、どこにあっても拒否する語(`deny_words`)を `Bash(<コマンド>:*)` の形へ変換したもの(`default_deny_rules`。「,」や括弧を含む項目は除く)で、雛形と、settings.json が空のときに渡す内容に使う。拒否が許可より優先される。
  - アプリが決める拒否(`--disallowedTools`): Web 検索を無効にしているエージェントでは `WebFetch` と `WebSearch` を拒否する(コマンド実行の可否は settings.json だけで決める)。ツールなしの単発の呼び出しでは、標準のツールをすべて拒否する。
  - コマンド権限(`command-policy.json`)は渡さない。Bedrock 方式(ワークは常に)ではコマンドがホストで動かないため、画面に Command Policy を出さない。
  - 許可されないツールは実行されず、その旨がツールの結果として Claude Code に返る。
- 画面での承認(実行中に確認を挟む)は「後回しにした項目」。

## 既存機能との関係

- サンドボックスが有効なとき、エージェントの会話は Claude Code に一本化する。ホスト側のツールループ(ファイル操作ツール・`run_command`・スキルのツール・Web 検索のサーバーツール)は使わない。
- 会話の記録・画面表示・音声の読み上げは、これまでどおりアプリ側で行う(回答のテキストを受け取って使う)。
- **ナレッジ整理(バッチ)と聞き取りの校正**: ワークのエージェントでは、コンテナ内の Claude Code を**ツールなしの単発**(`claude -p`、`--resume` なし、許可ツールなし・既定のツールをすべて拒否。`sandbox_agent::complete`)で呼ぶ。接続先・モデルは LLM タブの Claude Code の設定に従い、アプリのモデル選択(`batch_route`)は使わない(保存済みの値は無視する)。
  - 整理: 上限時間は設定の「1回の指示の上限時間」。
  - 校正: オフ / コンテナ内の Claude Code(`proofread_route` の `provider` が `sandbox`。上限 60 秒。発話のたびに起動するため数秒かかる)から選ぶ。既定はオフ。端末内の Qwen を保存していたときはオフとして扱う。失敗・時間切れのときは元の文字列を使う。
- 会話の要約(`compact`)・ホスト側のツールループは、Bedrock 方式(ワークは常に)では通らない(会話が Claude Code に移っているため)。API 方式のパーソナルとリーダーのために残している。
- コンテナでの実行(`sandbox::exec`。イメージ・コンテナ・環境変数・伏せ字・中断)は、Claude Code の実行と、ホスト側のツールループの `run_command` のコンテナ実行で共有する。会話がコンテナへ移ったため、`run_command` のコンテナ実行は会話からは使われない。

## Dockerfile(共通と、エージェント専用)

- 共通: `<アプリデータ>/sandbox/Dockerfile`(1つ)。初めて使うとき、同梱の標準(`src-tauri/resources/sandbox/Dockerfile`)をコピーする。全体設定画面の Sandbox Image で編集する。
- 専用: `<ワークスペース>/agent-sandbox/Dockerfile`(ワーク: `work/<UUID>/agent-sandbox/`、パーソナル: `<アプリデータ>/agent-sandbox/`)。**登録があれば共通より優先**する。エージェントの設定画面(Sandbox タブ)で、共通の内容をコピーして登録し、編集する。画面では、登録なしを「全体設定を利用」(共通を直接使うので、共通の変更に常に追従する)、登録ありを「個別設定を使用中」と表す。「全体設定を利用」で登録を解除すると共通へ戻る。登録後に共通を変更しても、専用には反映されない。
- 編集の方法は2つで、どちらも同じファイルを触る。
  - 画面内: テキストエリアで編集して「保存」(空・256KB 超・NUL 文字を含む内容は保存できない)。
  - 外部のエディタ: 「ファイルを表示」で Finder に出して編集。画面へ戻ると(編集中でなければ)自動で読み込み直す。
- イメージ名は Dockerfile の内容のハッシュで決まる。変更すると、次の指示(または「イメージをビルド」)で1回だけ再ビルドし、そのイメージを使うエージェントのコンテナを作り直す(専用ボリュームは残る)。古いタグは使われなくなってから消す。
- ビルドの文脈は Dockerfile のフォルダだけ。環境変数・認証情報はビルドに渡さない。ビルドは全体で1本ずつ。進捗は `sandbox-build-progress` イベント(`scope` は `shared` かエージェント ID)。
- 標準の内容: `node:22-bookworm-slim`(Claude Code は Node.js 22 以上が必要)に、AWS CLI v2・git・jq・ripgrep・python3 と、Claude Code(`@anthropic-ai/claude-code`、版を固定。現在 2.1.311)を入れたもの。Claude Code の版は Dockerfile の `CLAUDE_CODE_VERSION` を書き換えて更新する。読み取り専用のファイルシステムで動くため、自動更新は止める(`DISABLE_AUTOUPDATER=1`)。
- 崩してはいけない前提: 非 root のユーザー `agent`、`/knowledge` `/home/agent`(テンプレートは `/workspace` も作るが、マウントには使わない)、`sh` と `setsid`(util-linux)、`claude` コマンド。コンテナを作った直後に、`setsid`・`agent`・`claude` を診断し、満たさなければエラーにする。

## 名前とエージェントの対応

- コンテナ名は `myassistant-<ランダム8桁>`。名前にエージェントの名前や ID を含めない。
- 持ち主はラベル `myassistant.agent=<エージェントID>` で持つ(専用イメージ・ネットワークにも付ける。共通イメージは `myassistant.shared-image=1`)。
- 設定画面の「コンテナ名」で確認できる。`docker ps --filter label=myassistant.agent=<ID>` でも引ける。
- ネットワークとボリュームは ID から決まる名前(`myassistant-net-<ID>`、`myassistant-home-<ID>`)。

## 分離の内容

- マウントは上の表のものだけ。アプリデータ・`~/.aws`・ほかのエージェントのフォルダはコンテナから見えない。
- `--read-only`(`/tmp`・`/var/tmp` は tmpfs)、`--cap-drop ALL`、`no-new-privileges`、`--init`、非 root(`agent`)、メモリ 2GB・CPU 2・プロセス 512 の上限。
- エージェントごとにネットワークを分け、コンテナ同士は通信できない。外向きの通信は制限しない。

## コンテナの寿命と後始末

- コンテナは最初の実行で作り、使い終えても置いておく。最後の実行から約10分で停止し、アプリの終了時と起動時にすべて止める。
- エージェントを削除すると、コンテナ・ネットワーク・ボリューム・専用イメージを消す(共通イメージは残す)。
- バックアップには `sandbox.env`(平文)、共通の Dockerfile(`sandbox/`)、専用の Dockerfile(`agent-sandbox/`)を含める。専用ボリューム(`~/.claude` のセッションを含む)は含めない。

## 設定画面

- 全体設定画面の Sandbox: スイッチ。
- 全体設定画面の Sandbox Image: 共通の Dockerfile の編集・ビルド・状態。
- 各エージェントの「Sandbox」タブ(リーダーにも出る):
  - 有効/無効の表示、Docker・コンテナの状態、コンテナ名、コンテナを作り直す。
  - 担当システムのフォルダ(`/knowledge/data`)の場所の表示、「Finder で開く」、注意書き。
  - 1回の指示の上限時間(`sandbox_llm`。設定の書き出し・コピーの対象)。
  - 専用の Dockerfile の登録・編集。
  - Claude Code の settings.json のエディタ(モデル・許可・拒否もここ。空のときは許可・拒否の雛形を入れるボタン。貼り付け・保存・変更を破棄・再読み込み。`sandbox_claude_settings`。設定の書き出し・コピーの対象)。
  - `sandbox.env` のエディタ(値を含めて表示・編集、保存・変更を破棄・再読み込み・ファイルを表示)と、渡す変数の名前・検証結果。
- 実行ログと進行中の表示は、Claude Code のツール(`Bash`・`Read`・`Edit` など)を分かる名前で表示する。

## 決定事項

- docker CLI だけに対応する(Docker Desktop / OrbStack など)。探す場所は `/usr/local/bin` `/opt/homebrew/bin` `/Applications/Docker.app/Contents/Resources/bin` `~/.orbstack/bin` と `PATH`。
- コンテナ内は Linux。`brew` `open` `osascript` などホストの macOS 固有のコマンドは使えない。
- 外向きのネットワークは制限しない。
- Claude Code の API キーは、アプリに登録したものを実行ごとの環境変数で渡す(コンテナへファイルとして置かない。`sandbox.env` の同名が優先)。2026-11-10 に、以前の「アプリのキーは渡さない」から変更した。
- `sandbox.env` は、値を含めて画面で表示・編集する(2026-11-10 に決定。以前は名前だけを返していた)。
- 初版では実行中の承認を挟まない(許可・拒否のリストで制御する)。

## 既知の限界

- 同じ Docker ホスト上の root 権限を持つ者や、Docker の脆弱性までは防がない(コンテナによる分離の範囲)。
- コンテナ内の Claude Code とコマンドは、渡された認証情報の値を読める。外向きの通信を制限しないため、値を外へ送ることも技術的には可能。渡すのは、そのエージェントが使う分だけにする。
- 実行中、`sandbox.env` の値は docker CLI のプロセスの環境変数にある。同じユーザーの別プロセスから短時間見える可能性がある。
- `sandbox.env` の値(API キーなど)は設定画面にそのまま表示される。画面の共有やスクリーンショットに注意する。
- `/knowledge`(`data/` を含む)は読み書きでマウントするため、コンテナ内の作業でホスト側のファイルが変更・削除されうる。
- 1回の指示が AWS の一時キーの期限を超えると、途中で AWS の呼び出しが失敗する。
- 端末内の LLM(`local_llm`)は、Docker for Mac のコンテナでは GPU(Metal)を使えないため、コンテナ内では実用的な速度にならない。
- 同梱テンプレートの更新は、各 Dockerfile へ自動反映されない(共通の Dockerfile を編集済みのとき)。
- `sandbox.env` は認証情報を含むため、全体設定にしない(エージェントごとにだけ持つ)。
- 拒否ルールは Claude Code のコマンドの接頭辞の判定に従う。`deny_words`(どこにあっても拒否する語)も接頭辞のルールとして渡すため、ホスト側の判定ほど厳密ではない。
