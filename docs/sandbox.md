# サンドボックス(エージェント別の Docker コンテナ)

ワークのエージェントごとに、コマンドを専用の Docker コンテナの中で実行する機能です。エージェントごとに別の認証情報(AWS アカウントなど)を持たせ、ほかのエージェントや端末の認証情報に触れさせないために使います。

- 対象は**ワークのエージェントだけ**です。パーソナルとリーダーは対象外で、従来どおりホストで実行します。
- 設定はエージェントごと(`sandbox_enabled`、既定は無効)。設定画面の「権限」タブ → Sandbox で切り替えます。
- LLM との通信・ツールのループ・承認・コマンドの判定は、これまでどおりアプリ(ホスト)側で動きます。コンテナは、許可されたコマンドの実行先として使い、終了コードと出力をアプリが受け取ります。ファイル操作ツール(`create_file` など)もホスト側で、ナレッジを直接読み書きします。

## 構成

```text
[アプリ(ホスト)]
  tool_loop → command_policy(判定・承認)→ services/sandbox.rs
                 ├─ 作業ディレクトリをナレッジ配下に限り、/workspace/... へ変換
                 ├─ sandbox.env と AWS の一時キーを、実行ごとに環境変数として渡す
                 └─ docker exec(出力の逐次通知・タイムアウト・中断は shell.rs と共通)

[Docker]
  myassistant-<ランダム8桁>  /workspace  = そのエージェントのナレッジ(bind mount)
                             /home/agent = 専用ボリューム myassistant-home-<UUID>
  ネットワーク myassistant-net-<UUID>(エージェントごとに別)
```

## 名前とエージェントの対応

- コンテナ名は `myassistant-<ランダム8桁>` で、コンテナを作るときに決めます。名前にはエージェントの名前も ID も含めないため、`docker ps` だけでは持ち主は分かりません。
- 持ち主は**ラベル**で持ちます(`myassistant.agent=<エージェントID>`。イメージ・ネットワークにも付けます)。アプリはこのラベルでコンテナを探します。
- どのエージェントのコンテナかは、そのエージェントの設定画面(権限タブの Sandbox)の「コンテナ名」で確認できます。`docker ps --filter label=myassistant.agent=<ID>` でも引けます。
- コンテナを作り直す(イメージの変更・ナレッジの場所の変更・「コンテナを作り直す」)と、新しい名前になります。エージェント名を変えても名前は変わりません。
- ネットワークとボリュームは、データを失わないよう ID から決まる名前です(`myassistant-net-<ID>`、`myassistant-home-<ID>`)。

## 分離の内容

- マウントは、ナレッジ(`/workspace`)と専用ボリューム(`/home/agent`)の2つだけです。アプリデータ・`~/.aws`・ほかのエージェントのフォルダは存在しません。
- コンテナは `--read-only`(`/tmp`・`/var/tmp` は tmpfs)、`--cap-drop ALL`、`no-new-privileges`、`--init`、非 root(`agent`)、メモリ 2GB・CPU 2・プロセス 512 の上限で動きます。
- エージェントごとにネットワークを分け、コンテナ同士は通信できません。外向きの通信は制限しません。
- 作業ディレクトリ(`cwd`)はナレッジ配下に限ります。`/workspace/...`、ナレッジ配下の絶対パス、ナレッジからの相対パスを受け付け、`..` とシンボリックリンクは解決してから判定します。
- **Docker が使えないとき(未導入・停止中)は、ホストでの実行へ切り替えず、エラーを返します。**

## Dockerfile(エージェントごと)

- 置き場所: `<アプリデータ>/workspaces/<UUID>/sandbox/Dockerfile`。サンドボックスを初めて有効にしたとき、アプリ同梱の標準(`src-tauri/resources/sandbox/Dockerfile`)をコピーします。以後は自由に編集できます。
- 標準の内容は Debian slim に AWS CLI v2・git・jq・python3・node などを入れたものです。
- 標準のテンプレートが更新されても、各エージェントのコピーは自動では上書きしません。設定画面の「標準に戻す」(確認つき)で上書きできます。
- イメージ名は `myassistant-sandbox-<ID先頭8桁>:<Dockerfile内容のハッシュ>`。Dockerfile を編集すると次のコマンド実行時に自動で再ビルドし、コンテナを作り直します(専用ボリュームは残ります)。古いタグのイメージは消します。
- ビルドの文脈は `sandbox/` フォルダだけです(`COPY` したいファイルはここに置けます)。`sandbox.env`・`secrets.json`・`timeline.db` は文脈の外にあるため入りません。環境変数・認証情報はビルドには渡しません(`--build-arg` を使いません)。ビルドは全体で1本ずつです。
- 編集しても崩してはいけない前提: 非 root のユーザー `agent`、`/workspace` と `/home/agent`、`sh` と `setsid`(util-linux)。コンテナを作った直後に診断し、満たさなければエラーにします。
- 進捗は `sandbox-build-progress` イベント(ワークスペース ID 付き)で画面に流れます。

## 環境変数(`sandbox.env`)

- 置き場所: `<アプリデータ>/workspaces/<UUID>/sandbox.env`(dotenv 形式、権限 0600)。有効にしたとき、説明コメント入りの空ファイルを作ります。コンテナにはマウントしません。
- 書式: `NAME=value`(1行に1つ)。`#` のコメント、`export ` の接頭辞、`"..."` / `'...'` の囲みに対応します。複数行の値は使えません。
- **実行のたびに読み直す**ので、保存すれば次のコマンドから反映されます(再起動・コンテナの作り直しは不要)。
- 検証: 名前は英数字と `_`(数字から始まらない)。`PATH` `HOME` `USER` `TERM` など実行の仕組みが使う名前と、`DOCKER_` `LD_` `DYLD_` で始まる名前は指定できません(docker CLI の動作を変えてしまうため)。最大 100 個、値は 8KB まで、制御文字は不可。不正な行があれば、実行前に「N行目」を示してエラーにします(値はエラーに含めません)。
- 画面には名前と検証結果だけを返し、値は返しません。編集はエディタで行います(画面の「ファイルを表示」で Finder に出せます)。
- AWS: このエージェントに AWS(Bedrock)の設定が登録されていれば、選択中のプロファイルの認証情報(`AWS_ACCESS_KEY_ID` `AWS_SECRET_ACCESS_KEY` `AWS_SESSION_TOKEN` `AWS_REGION` `AWS_DEFAULT_REGION`)も実行ごとに渡します。ロールを引き受けるプロファイルは、Bedrock の呼び出しと同じ流れ(MFA の入力・メモリ上のキャッシュ)で一時キーを得ます。`sandbox.env` に同じ名前があれば、そちらが優先されます。AWS の認証情報を取れなかったときは、その認証情報なしでは実行せずエラーにします。
- 値の渡し方: `docker exec -e NAME` の形で**名前だけを引数に書き**、値は docker CLI の環境変数として渡します。コンテナの作成時の設定には入れないので、`docker inspect` に値は残りません。値が見えるのは、実行中の docker CLI のプロセスの環境と、コンテナ内のその実行のプロセスだけです。
- 出力の伏せ字: 8 文字以上の値が stdout / stderr に出たら `***` に置き換えてから、画面と LLM へ渡します(読み取りの境界で分かれた値も伏せます)。`*REGION` で終わる名前の値は秘密でないため対象外です。コマンド側で値を変形して出力した場合(Base64 など)は検知できません。
- `command_policy` の保護対象(`protected`)に `sandbox.env` を含めているため、ホストで実行するコマンドからも触れません。

## 実行と中断

- コンテナは、最初の `run_command` で作って起動し、使い終えても置いておきます(インストールしたツールやキャッシュが残ります)。最後の実行から約10分でコンテナを停止し、アプリの終了時にすべて止めます。アプリの起動時にも、前回から動いたままのコンテナを止めます。
- コマンドは `docker exec ... setsid -w sh -c` で新しいセッションとして起動し、プロセスグループの ID を `/tmp` に記録します。**時間切れ・中断・通常の終了のたびに**、そのグループを `docker exec` で止めます(docker CLI を止めてもコンテナ内のプロセスは残るため。背景に残した子孫も止まる)。
- タイムアウトは既定 60 秒、最大 600 秒で、ホスト実行と同じです。

## 後始末

- エージェントを削除すると、別スレッドでコンテナ・ネットワーク・ボリューム・イメージを消します(失敗しても削除は続行。見つからなくてもよい)。ワークスペースのフォルダ(Dockerfile・`sandbox.env`)はこれまでどおり丸ごと消えます。
- バックアップ([backup.md](backup.md))には `sandbox.env`(平文)と `sandbox/` を含めます。リストア後、イメージとコンテナは次のコマンドで作り直されます。

## 設定画面

「権限」タブの Sandbox(パーソナル・リーダーでは出ません)。

- スイッチ(`sandbox_enabled`)。設定の書き出し・コピーの対象です(環境変数と Dockerfile は含まれません)。
- Docker の状態(未導入 / 停止中 / 使える)、イメージ(未ビルド / ビルド中 / 準備済み)、コンテナ(実行中 / 停止)。
- Dockerfile: 状態(標準 / 編集済み)、ファイルを表示、標準に戻す、イメージをビルド、コンテナを作り直す。
- `sandbox.env`: 定義されている名前の一覧、検証結果、ファイルを表示、再読み込み。

## 決定事項

- docker CLI だけに対応します(Docker Desktop / OrbStack など)。探す場所は `/usr/local/bin` `/opt/homebrew/bin` `/Applications/Docker.app/Contents/Resources/bin` `~/.orbstack/bin` と `PATH` です。
- コマンドは Linux(arm64 / x86_64 は Docker 側に従う)で動くため、`brew` `open` `osascript` などホストの macOS 固有のコマンドは使えません。
- 外向きのネットワークは制限しません。

## 既知の限界

- 同じ Docker ホスト上の root 権限を持つ者や、Docker の脆弱性までは防ぎません(コンテナによる分離の範囲)。
- 実行中、`sandbox.env` の値は docker CLI のプロセスの環境変数にあります。同じユーザーの別プロセスから短時間見える可能性があります。
- 同梱テンプレートの更新は、各エージェントの Dockerfile には自動反映されません。
- Apple `container`、許可ドメインだけを通すネットワーク制限、パーソナル / リーダーのコンテナ化は未対応です。
