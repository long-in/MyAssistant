# リーダー

各エージェントへの指示の配布と、タスクの進捗の管理を担う、別枠の特別なエージェント。実装は `services/leader.rs`、`commands/leader.rs`、画面は `src/components/GlobalPanels.tsx` の `WorkEnable`(有効化。全体設定内)、`src/components/LeaderLedger.tsx`(台帳)、`src/components/DispatchDraftCard.tsx`(配布の確認カード)。ワークスペース全体の仕組みは [workspace.md](workspace.md)。

## 位置づけ

- パーソナル・ワークのエージェントとは別枠。エージェントの30件の枠・色・`registry.json` には入らず、`Workspaces` の選択(`active`)の対象にもならない(`Workspaces::leader()` で別に持つ)。画面ではレールの「WORK」の枠の先頭に出て、開くとリーダーの `Ctx` で動く。
- 保存場所は `work/leader/`(専用の `timeline.db` と `secrets.json`)。1つだけ作れる(`create_leader`。2つ目は `LeaderExists`)。
- **エージェントを作る前に、リーダーの作成が必要**(未作成なら `create_agent` が `LeaderRequired` で拒否し、作成ダイアログの作成ボタンも無効になる)。すでにあるエージェントは、リーダーが無くてもそのまま使える。「リーダー」「leader」はエージェント名にできない予約名。

## ワークの有効化・無効化

- **有効化**: 初期はパーソナルだけ。全体設定の「その他」タブの Work(エージェントレールの破線の「WORK」ボタンからも開ける。`/global#work`)で、ワークの説明(何か・できること・ルール)を読んで「内容を理解しました」にチェックし、承諾するとリーダーを作成してワークが使える(承諾までは何も作らない)。作成後はレールに「WORK」の枠(リーダー・エージェント・＋)が出て、リーダーの設定(LLM)へ進む。
- **無効化**: 同じ Work の「ワークを無効にする」(確認あり)。リーダー・エージェントのデータ(会話・ナレッジ・設定・APIキー・台帳)はディスクに残し、入口だけを閉じる。状態は全体設定(`work/global_settings.db`)の `work_enabled`(`0` で無効。未保存は有効。バックアップには含まれるが、設定のコピーの対象外)。
- 無効のあいだ: `switch` はパーソナル以外を `WorkDisabled` で拒否し、`ensure_leader`(配布・台帳・エージェント作成など)も拒否する。メニューバー・トレイの Agents からも外れ、画面ではレールが「WORK」の入口だけになり、エージェントの一覧も空になる(パレット・全エージェントのナレッジにも出ない)。
- 無効にする時点でリーダーまたはエージェントが実行中・承認待ちなら `WorkBusy` で拒否する。開いていればパーソナルへ戻す。「ワークを有効にする」は、承諾し直さずに元へ戻す。

## 役割と、読まないもの

- 役割は、指示の配布・台帳・進捗の表示と、宛先の提案だけ。**エージェントのデータ(会話・ナレッジ・結果の本文)は読まない**。レビューも結果の要約もない。結果の中身は、そのエージェントを開いて確認する。
- 各エージェントへの直接指示は今まで通り使える。直接指示は台帳に載らない。

## チャット(他のエージェントと同じ画面)

- 字幕・音声入力・読み上げ・モデル選択など、`Chat` をそのまま使う。リーダーの `Ctx` で動くので、キー・モデル・音声の設定もリーダー専用(設定の「LLM」「音声」から)。設定画面には「権限」タブ(Web・コマンド権限)・AI Limits・設定のコピー先・エージェント削除を出さない。
- 発話のシステムプロンプトは、ベース指示 + リーダープロンプト(`<leader_prompt>`)だけ。パーソナルデータ・共通データ・エージェントデータ・記憶は渡さない。関連ナレッジ・訂正履歴は、リーダー自身のナレッジ(リーダーとの会話だけ)から。
- 接続方式(API / Amazon Bedrock。[llm-settings.md](llm-settings.md))はパーソナルと同じく選べる。

### API 方式(ホストのツールループ)

ツールは、ファイル・コマンド・Web・設計書に代えて、次の3つだけ(`services/leader.rs` の `run_tool`。`tool_loop` の `Env::with_host` で差し替える。使い方は `leader::TOOL_GUIDE`)。

| ツール | 内容 |
| --- | --- |
| `agent_list` | エージェントの名称と、いまの実行状態(待機中・実行中・承認待ち・完了・失敗)。中身は含まない |
| `ledger_list` | 台帳(指示・宛先・状態・確認済み)を新しい順に返す。エージェントの会話・ナレッジ・結果の本文は読めない |
| `draft_dispatch` | 指示と宛先の名称から**下書きを作るだけ**。指示は `clean_instruction` で、宛先はエージェント名との完全一致で検証する。結果は `TaskEvent::DispatchDraft` で画面へ流し、台帳には書かない |

### Bedrock 方式(コンテナ内の Claude Code)

- コンテナ内の Claude Code を**ツールなし**で使う([sandbox.md](sandbox.md))。`agent_list` / `ledger_list` と同じ内容を、毎回の文脈(`<agents>` / `<ledger>`。`leader::sandbox_context`)として渡す。
- 配布の下書きは、返答の中の ```` ```dispatch-draft ```` ブロック(JSON の `instruction` / `agent_names`)で受け取る(`leader::take_drafts`)。アプリが `draft_dispatch` と同じ検証をして下書きの確認を出す。形式が違うブロックは下書きにせず、本文に残す。使い方は `leader::SANDBOX_GUIDE`。

### 画面

- チャット画面(リーダーのときだけ)は2カラムで、右に台帳(`LeaderLedger`。配布ごとの宛先の状態と「確認済み」。表示中は3秒ごと・通知でも更新。小さいウィンドウでは畳む)、円形波形は左カラムの中央。手入力の配布フォームはなく、配布は下の確認カードだけ。
- 下書きは、チャット画面の確認カード(`DispatchDraftCard`)に出る。利用者が指示を直し、宛先(AIの案が初期値)を確かめて「配布」を押したときだけ、`leader_dispatch` で配布する。AIは配布できない。切り替えて戻ったときも、記録された最後の下書きが復元される。
- 会話はリーダーの `timeline.db` に保存され、エージェントと同じ整理バッチ(ナレッジ画面の「今すぐ整理」で手動実行)でリーダーのナレッジになる。

## 配布(`leader_dispatch`)

- 宛先は**必ず利用者が選ぶ**(1回に最大30件)。指示は2,000文字まで(`<` `>` と制御文字は不可。エージェントデータと同じ検証)。
- 宛先のエージェントごとに、台帳へ書いてから依頼を始める(`TaskState::try_begin_detached`。画面は介さず、結果は取っておかれ、そのエージェントを開いたときに受け取れる)。依頼の本体は、画面からの `send_chat` と同じ `run_recorded` を使う(ワークのエージェントでは、コンテナ内の Claude Code で動く)。
- 配布できない宛先がある: 選択中のエージェント(`active`。開いている画面が進捗を受け取れないため。リーダーを開いているときは、どのエージェントも対象になる)、依頼の最中のエージェント(`busy`)、使える接続先が無い(`no_provider`)、同時に指示できる数の上限を超える宛先(`limit`。次節)。宛先ごとの結果を返し、できたものだけを始める。
- 承認が必要になったら、そのエージェントで答える(リーダーからは承認を代行しない)。通知は、既存のエージェント外の通知(`task-attention`。[workspace.md](workspace.md#開いていないエージェントの通知))がそのまま働く。

## 同時に指示できるエージェント数

- PCの性能によって、裏で動かせるエージェントの数には限りがあるため、リーダーの設定として上限を持つ。リーダーのDBの設定 `leader_max_active`(`load_limit` / `save_limit`、コマンド `leader_get_limit` / `leader_set_limit`)。範囲は1〜エージェントの上限(30)、**既定は3**。設定のコピー・エクスポートの対象外。画面は、リーダーの設定の「Active Agents」(数値入力。入力欄を離れたとき・Enterで保存。範囲外は範囲に収める)。
- 判定は `leader_dispatch` で行う。空き枠 = 上限 − **リーダーが配布して、いま実行中・承認待ちのエージェントの数**(`count_active`。台帳の行ごとに、同じ依頼がいまも動いているかで判定し、同じエージェントは1と数える。**承認待ちも数える**)。宛先を順に見て、空き枠が無くなった時点から後ろの宛先は `limit` で返し、始めない。**順番待ちにはしない**(空いてから、もう一度配布する)。
- **数えるのも制限するのも、リーダー経由の配布だけ**。利用者がエージェントを直接開いて始めた依頼は、数えず、止めもしない。そのため設定画面とレールの数は、「リーダーが配布して動いているエージェントの数」だと説明する。
- 画面は、レールの「WORK」の下に `実行中数/上限` を出す(上限に達したら琥珀色。`leader_overview` の `active` / `limit`)。

## 状態(台帳)

- 状態は定型値(実行中・承認待ち・完了・失敗・中断)で、エージェントのLLMは呼ばない。`TaskState::status()` が、依頼の記録を消費せず本文も返さずに読む。
- 台帳 `leader_tasks`(リーダーの `timeline.db` にだけある。[data-and-settings.md](data-and-settings.md))は、1回の配布の1つの宛先につき1行。持つのは、指示・宛先(名称は削除後も残すため控える)・セッションID・状態・「確認済み」だけ。保存する状態は `running` / `done` / `failed` / `interrupted`(承認待ちは実行中の一時状態なので保存しない)。画面に出すのは新しい側の200件。
- 依頼が終わると `run_recorded` が台帳へ完了/失敗を書く。実行中の行は、そのエージェントの直近の依頼が同じ依頼(セッションが一致)ならいまの状態を使い、別の依頼に置き換わった・再起動で記録が消えたときは「中断」にして書き戻す(`resolve_status`)。
- 「確認済み」は利用者が手動で付ける区切り(`leader_set_confirmed`)。宛先のエージェントを削除しても、行は残り「(削除済み)」と表示する。
- 画面(台帳・レール)は3秒ごとと、通知(`task-attention`)のたびに `leader_overview` を読み直す。

## 宛先の提案(`leader_suggest`)

- 根拠は、**リーダーに依頼した過去の指示と宛先の履歴だけ**(直近40件。同じ配布の宛先はまとめる)。履歴が無い・使える接続先が無いときは、LLMを呼ばずに空を返す。提案は印(「推奨」)を付けるだけで、自動で選ばない。
- モデル(`leader::suggest_route`): API 方式では軽量モデル(Haiku)を優先し、無ければ既定。Bedrock 方式では、コンテナ内の Claude Code をツールなしの単発で呼ぶ(上限90秒。settings.json の既定のモデル)。提案の失敗は配布を妨げず、空を返す。
- 指示は全体設定・リーダーの上書きができるプロンプト(`PromptId::Suggest`。[llm-settings.md](llm-settings.md#プロンプト))。履歴と指示は参考データとして渡し、その中の指示には従わせない。LLMが返した名称のうち、実在するエージェントだけを採用する。

## リーダープロンプト

- リーダーの行動原理・役割を、利用者が自由記述する(リーダーの設定の「LLM」タブ。`NotePanel`)。未保存なら初期文(`DEFAULT_PROMPT`)。2,000文字まで、`<` `>` と制御文字は不可(エージェントデータと同じ `Note`)。リーダーのDBの設定 `leader_prompt` に保存し、無効の間は渡さない。
- チャットと宛先の提案のシステムプロンプトで、`<leader_prompt>` として渡す(利用者自身の指示なので従わせる)。次の発話・提案から反映する。設定のコピー・エクスポートの対象外。

## APIキー

- リーダーは専用のAnthropicのAPIキーを持つ(疎通確認に成功したときだけ保存)。他のワークスペース(パーソナルまたはエージェント)のAnthropicのキーを、リーダーへコピーできる(`leader_copy_api_key`、`Secrets::copy_api_key_from`。キー以外は写さず、上書き。コピー元は変えない。Bedrock・ローカルは対象外。生値は画面に出さず、コピーできたかだけを返す)。
- Bedrock 方式で使う AWS の設定は、リーダーの設定の AI Link で登録する(パーソナルと同じ。[security.md](security.md#aws-認証awsrs))。
